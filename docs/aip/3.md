# AIP-3：AIP 版本管理

本文定义 API Improvement Proposals（AIP）的版本管理方案。

## 指导原则

- AIP 必须按日期进行版本管理，使用 `YYYY-MM-DD` 的 ISO 8601 格式；该日期对应版本加入时的日期。
- AIP 的版本必须以标签形式存在于保存 AIP 的源代码管理系统中，格式为 `v{version}`。例如：`v2023-03-28`。
- 当一个或多个 AIP 发生重要变化时，必须产生新的版本。
- 每一份 AIP 都必须包含变更记录：注明变更日期并简要描述变化。

## 设计缘由

版本是引用特定时点 AIP 指导意见的锚点。这一点至关重要：某项指导可能被撤销，也可能经历重大变动，以至于与最初的建议不再相同。设计 API 时，团队可能需要引用当时的 AIP 指导来说明决策依据。

### 为什么采用基于日期的版本？

采用日期版本后，使用者可以方便地找到 API 编写时所适用的 AIP 指导。

### 为什么不让每份 AIP 单独版本化？

另一种做法是为每份 AIP 单独附加版本号。但 AIP 之间经常相互引用；若各自拥有版本，交叉引用也必须写明被引用文档的特定版本，才能保证引用上下文完整。这会显著增加维护与阅读成本。
