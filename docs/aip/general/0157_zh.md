# 部分响应

资源可能很大，或计算成本很高；API 有时需要让调用方控制返回哪些字段。

## 指导

API **可以**通过两种方式支持部分响应。

### 字段掩码参数

可以使用 `google.protobuf.FieldMask` 让调用方细粒度控制返回字段。API **应**通过旁路参数支持掩码，例如 HTTP 查询参数、请求头或 gRPC metadata；Google Cloud API 将其作为系统参数。字段掩码参数的值**必须**是 `google.protobuf.FieldMask`，不应把掩码放在请求消息中。

### View 枚举

如果只需要少量固定视图，API **可以**在请求中提供 `View` 枚举，例如 `BASIC` 和 `FULL`。枚举适合少量稳定、语义清晰的预定义视图；需要任意字段组合时应使用字段掩码。默认视图必须在文档中说明，并且新增字段不应无意中改变现有视图的成本或敏感性。

### 将 read mask 作为请求字段

通常不应在请求消息中定义 `read_mask` 字段，因为它会污染方法签名，并与系统参数及各语言客户端的通用部分响应机制冲突。只有 API 有明确的业务语义、无法使用旁路参数时才应例外。

## 设计缘由

使用旁路字段掩码可以保持请求消息稳定，让客户端、网关和基础设施统一处理读取投影；请求字段中的 `read_mask` 会把传输控制细节变成 API 业务契约，导致难以演进。
