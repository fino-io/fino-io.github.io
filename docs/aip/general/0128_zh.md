# 声明式友好的接口

许多服务需要与常见的 DevOps 工具交互，尤其是那些创建和管理可通过网络寻址的资源（例如虚拟机、负载均衡器、数据库实例等）的工具。这些工具围绕“配置即代码”的原则运作：用户指定完整的目标状态，工具负责完成达到该状态所需的全部变更。

这些工具是**声明式**的：它们不是指定要执行的具体*动作*，而是指定期望的*结果*，再根据当前状态与目标状态之间的差异推导出动作。

此外，流行的 DevOps 工具数量众多，而且每年还会不断出现新的工具。要将数百种资源类型集成到多个工具中，就需要保持统一，以便自动完成集成。

## 指导

### 资源

声明式友好的资源**必须**只使用具有强一致性的标准方法管理资源生命周期。这样工具才能通用地支持这些资源，并遵循其他声明式友好指导（见[延伸阅读](#延伸阅读)）。

声明式友好的资源**应**标明其遵循声明式友好风格：

```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
    style: DECLARATIVE_FRIENDLY
  };

  // 名称及其他字段……
}
```

### 协调

如果资源的更新需要一段时间（超过几秒）才能生效，资源**应**包含 `bool reconciling` 字段，以披露变更正在进行中。该字段**必须**是仅输出字段。

如果资源当前状态与用户期望状态不匹配，且系统正在协调二者，资源**必须**将 `reconciling` 字段设为 `true`。无论进入协调状态的根因是用户操作还是系统操作，都适用此要求。

**注意：** 服务响应 `GET` 请求时**必须**返回资源的当前状态，而不是期望状态。

## 延伸阅读

由于声明式友好的接口侧重于在资源之上实现自动化，相关指导会更加严格。以下是其他 AIP 中声明式友好指导的完整参考：

- 资源**不应**使用自定义方法：参见 AIP-136。
- 资源**必须**使用 `Update` 方法处理重复字段：参见 AIP-144。
- 资源**必须**包含特定标准字段：参见 AIP-148。
- 资源**必须**包含 `etag` 字段：参见 AIP-154。
- 资源**应**提供变更校验：参见 AIP-163。
- 资源**不应**实现软删除。如果 ID 无法重新使用，资源**必须**实现软删除和 undelete RPC：参见 AIP-164。
