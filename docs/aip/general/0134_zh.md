# 标准方法：Update

在 REST API 中，通常向资源 URI（例如 `/v1/publishers/{publisher}/books/{book}`）发送 `PATCH` 或 `PUT` 请求来更新资源。

面向资源的设计（[AIP-121][]）通过 `Update` 方法遵循这一模式。RPC 接收表示资源的 URI，并返回资源。

## 指导

除非用户使用没有价值，API **通常应**为资源提供 Update 方法。Update 方法用于修改资源而不产生副作用。

```proto
rpc UpdateBook(UpdateBookRequest) returns (Book) {
  option (google.api.http) = {
    patch: "/v1/{book.name=publishers/*/books/*}"
    body: "book"
  };
  option (google.api.method_signature) = "book,update_mask";
}
```

- RPC 名称**必须**以 `Update` 开头，其余部分**应**使用资源消息名称的单数形式；请求消息以 `Request` 结尾，响应消息就是资源本身。
- 响应**应**包含完整资源，并**必须**包含更新掩码中发送的字段（仅输入字段或部分响应除外）。长时运行时必须解析为资源本身。
- 方法**应**支持部分更新，HTTP 动词**应**为 `PATCH`。仅支持完整替换时可以使用 `PUT`，但不推荐，因为向资源新增字段会变成破坏性变更。
- 资源的 `name` 字段**应**映射到 URI 路径，并应是路径中唯一变量；HTTP 注解**必须**有映射到资源字段的 `body`。方法签名**应**为 `"{resource},update_mask"`。
- 管理平面上的更新应具备[强一致性][strong consistency]。

**注意：** 与其他标准方法不同，Update 的路径通常引用嵌套字段（如示例中的 `book.name`）；字段名包含分隔词时使用 `snake_case`。

### 请求消息

```proto
message UpdateBookRequest {
  Book book = 1 [(google.api.field_behavior) = REQUIRED];
  google.protobuf.FieldMask update_mask = 2;
}
```

请求**必须**包含资源字段，并映射到 PATCH 请求体；资源必须包含用于识别资源的 `name` 字段，并标识资源类型。支持部分更新时，必须包含名为 `update_mask`、类型为 `google.protobuf.FieldMask` 的可选字段。掩码相对于被更新的资源，而不是请求消息；省略掩码等同于更新所有已填充字段，并且必须支持特殊值 `*` 表示完整替换。调用方和 API 生产者都应谨慎使用 `*`，通常显式列出字段更安全。请求不得包含其他必填字段。

### 副作用

Update 的目标通常只是更新资源数据，**不应**触发其他副作用；副作用应由自定义方法触发。尤其是[状态字段][state fields]**不得**直接通过 Update 写入。

### PATCH 与 PUT

Google API 通常只使用 `PATCH`，不支持 `PUT`。API 会持续以向后兼容的方式在原版本中新增资源字段；若使用 `PUT`，旧客户端发送不认识新字段的完整资源时会覆盖这些字段，从而意外丢失数据。`PATCH` 配合字段掩码可以避免这一问题。

### 长时运行的更新

更新耗时较长时，API **应**使用 AIP-151 的长时运行操作，并在 `operation_info` 中同时指定 `response_type` 和 `metadata_type`。声明式友好的资源（AIP-128）**应**使用长时运行更新。

### 创建或更新

使用客户端分配资源名称时，Update **可以**暴露 `bool allow_missing`。资源不存在时，该字段会使 Update 创建资源，并忽略 `update_mask`；资源已存在时，仍只更新掩码列出的字段。调用方即使设置 `allow_missing` 为 `true`，也**必须**拥有更新权限；若不希望允许通过 Update 创建资源，应使用 IAM 条件限制。

### ETag

需要检测并避免竞态条件时，资源**应**包含服务端计算的不透明 `string etag` 字段。若请求提供 ETag，则仅当它与服务端当前值匹配时才应成功；否则必须返回 `ABORTED`。`update_mask` 不影响 ETag 校验。

### 昂贵字段

有些字段计算成本很高，或来自最终一致的多个数据源，更新时无法可靠返回。此时 API **可以**只返回更新过的字段并省略其余字段，但应在文档中明确说明。

### 错误

请参阅[错误][errors]，尤其是[何时使用 PERMISSION_DENIED 和 NOT_FOUND][permission-denied]。在拥有权限但资源不存在时，除非 `allow_missing` 为 `true`，服务**必须**返回 `NOT_FOUND`（HTTP 404）。
