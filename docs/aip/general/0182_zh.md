# 外部软件依赖

有些服务允许用户创建运行在外部软件上的资源，例如指定 PostgreSQL 版本的数据库、运行某操作系统的虚拟机，或使用某版本 Node.js 的应用。外部软件有自己的发布和生命周期，当前暴露的版本最终会到达生命周期终点。

**注意：** 本 AIP 当前为 Reviewing，稳定性低于 Approved AIP。

## 指导

服务**应**把外部软件版本建模为资源配置的一部分，并明确可用版本、默认版本、弃用时间、停止支持时间和迁移路径。版本字符串应由服务解释，不应让用户依赖供应商内部格式。

服务应区分“用户已创建资源仍可继续运行”和“不能再创建新资源”的日期，并提供升级、迁移或导出能力。停止支持时应提前通知，不能静默将用户资源升级到不兼容版本。

### 持续支持

只要服务承诺支持某外部版本，就应保持该版本的 API 语义、数据格式和安全补丁；若只能提供有限支持，必须在产品和 API 文档中明确。新版本可以并行提供，不应改变既有资源的版本字段。
