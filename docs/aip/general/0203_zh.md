# 字段行为文档

定义 Protocol Buffers 字段时，通常需要向用户说明字段行为的某些方面（例如字段是必需还是可选）。此外，让其他工具理解这些行为也很有用（例如优化客户端库签名）。

## 指导

API 使用 `google.api.field_behavior` 注解描述易于理解的字段行为，例如字段是否必需或不可变。

```proto
// 要识别的音频数据。
RecognitionAudio audio = 2 [(google.api.field_behavior) = REQUIRED];
```

- API **必须**为请求中使用的消息或子消息上的每个字段应用 `google.api.field_behavior` 注解。
  - 资源消息中的 AIP-154 `etag` 字段例外：该字段**不应**分配任何 `google.api.field_behavior`。
  - 此外，`oneof` 字段**可以**省略 `google.api.field_behavior`，但在这种情况下**应**在注释中记录具体行为。
- 注解**必须**包含能够准确描述字段行为的所有 [google.api.FieldBehavior][] 值。
  - **不得**使用 `FIELD_BEHAVIOR_UNSPECIFIED`。
- API 至少**必须**使用 `REQUIRED`、`OPTIONAL` 或 `OUTPUT_ONLY` 中的一个。

**警告：** 虽然 `field_behavior` 不影响 proto 层面的行为，但许多客户端（例如 CLI 和 SDK）依赖它们生成代码。新增字段时应仔细审查并考虑哪些值适用。

没有注解的字段，为了向后兼容会被解释为 `OPTIONAL`。尽管如此，**不得**省略该注解。

**注意：** 本文给出的词汇仅用于*描述*，本身不会增加任何验证。其目的是以一致方式为客户端记录字段行为。

### 嵌套消息的字段行为

嵌套消息上的 `google.api.field_behavior` 注解与父字段的注解相互独立。

例如，嵌套消息可以有 `REQUIRED` 字段行为，而父字段为 `OPTIONAL`：

```proto
message Title {
  string text = 1 [(google.api.field_behavior) = REQUIRED];
}

message Slide {
  Title title = 1 [(google.api.field_behavior) = OPTIONAL];
}
```

在上例中，如果指定了 `title`，则 `text` 字段是必需的。

## 词汇

### 标识符

使用 `IDENTIFIER` 表示资源消息中的某个字段用于标识资源。它**必须**附加到 `name` 字段，且**不得**附加到任何其他字段（见[表示资源名称的字段][fields representing resource names]）。

`IDENTIFIER` 表示在创建方法中，该字段不接受输入（即 `OUTPUT_ONLY`），同时在以资源作为主要输入的变更方法（例如[标准 Update][aip-134]）中被视为 `IMMUTABLE` 并接受输入。

此注解**不得**应用于消息中对其他资源的引用。

### 不可变

使用 `IMMUTABLE` 表示资源上的字段在创建后不能更改。这既适用于输入或输出字段，也适用于必需或可选字段。

服务在更新请求（或类似请求）中收到不可变字段时，即使该字段包含在更新掩码中，如果值没有变化，服务**应**忽略该字段；如果请求修改值，则**应**返回 `INVALID_ARGUMENT` 错误。

不可变字段的潜在使用场景（并非完整列表）包括：

- 在应用生命周期内不可修改的资源属性（例如磁盘类型）。

**注意：** “条件不可变”的字段**不得**添加不可变注解。

### 仅输入

使用 `INPUT_ONLY` 表示字段在请求中提供，而对应字段不会包含在输出中。

此外，只有当字段属于资源消息，或属于资源消息中包含的消息时，才**应**将其描述为仅输入。特别是，请求消息中的字段（只作为 RPC 参数的消息，名称通常以 `Request` 结尾）**不应**描述为仅输入，因为这一点已经由其语义暗示。

仅输入字段的潜在使用场景（并非完整列表）包括：

- AIP-214 中描述的 `ttl` 字段。

**警告：** 仅输入字段很少见，使用前应仔细考虑。

### 可选

使用 `OPTIONAL` 表示字段不是必需的。

如果字段属于请求消息（作为 RPC 参数的消息，名称通常以 `Request` 结尾）或子消息，则**可以**将其描述为可选。

**注意：** 字段存在性标签 `optional` 与字段行为 `OPTIONAL` 并不互斥。更多信息请参阅 AIP-149。

### 仅输出

使用 `OUTPUT_ONLY` 表示字段在响应中提供；但将字段放入请求消息不会产生任何作用（服务器**必须**清除该字段中的值，且**不得**仅因为输入中存在该字段的值而抛出错误）。同样，在更新字段掩码中出现仅输出字段时，服务**必须**忽略它（参见 AIP-161）。

此外，只有当字段属于资源消息，或属于资源消息树中更深层的消息时，才**应**将其描述为仅输出。特别是，响应消息中的字段（只作为 RPC 返回值的消息，名称通常以 `Response` 结尾）**不应**描述为仅输出，因为这一点已经由其语义暗示。

如果适合 API，仅输出字段**可以**设置为空值。

仅输出字段的潜在使用场景（并非完整列表）包括：

- 创建或更新时间戳。
- 根据原始用户输入派生或结构化的信息。
- 由服务分配且不能修改的资源属性。

### 必需

使用 `REQUIRED` 表示字段在请求或资源中**必须**存在（且被设置为非空值）。

字段只有在以下任一条件成立时，才**应**描述为必需：

- 字段属于用户在某处提供的资源输入。在这种情况下，只有存储了“真值”，资源才有效。
  - 创建资源时，创建请求**必须**提供该字段的值（参见[创建][aip-133]）。
  - 更新资源时，如果字段掩码中也没有该字段，表示不改变该字段，则用户**可以**省略它；否则**必须**提供。
- 字段属于请求消息（作为 RPC 参数的消息，名称通常以 `Request` 结尾）。在这种情况下，请求中**必须**提供该值；未提供**必须**导致错误（通常是 `INVALID_ARGUMENT`）。

上文的“真值”定义如下：

- 对于原始类型：不是 `0`、`0.0`、空字符串/字节和 `false` 的值。
- 对于重复字段和映射：至少有一项的值。
- 对于消息：至少有一个“真值”字段的消息。

以下字段**不应**描述为必需：

- 始终存在于响应中的字段。
- 在某些情况下才必需的字段。
- 任何不作为用户输入使用的消息（包括资源消息）中的字段。

**注意：** 大多数情况下，空值（例如布尔值 `false`、整数 `0` 或枚举的未指定值）无法与未设置区分，因此将必需字段设置为假值会产生错误。其推论是，必需的布尔字段必须设置为 `true`。

### 无序列表

在资源的重复字段上使用 `UNORDERED_LIST`，表示服务不保证列表项的顺序。

如果服务不保证元素顺序与用户发送的顺序一致（包括服务会代用户对列表排序的情况），字段**应**描述为无序列表。

带有无序列表的资源**可以**以稳定顺序返回列表，也**可以**以随机、不稳定的顺序返回列表。

## 向后兼容性

增加或修改 `google.api.field_behavior` 值，可能代表 API 的语义变化，现有客户端可能将其视为不兼容。以下是使用 `google.api.field_behavior` 的向后不兼容变更示例：

* 为之前被视为 `OPTIONAL`（隐式或显式）的现有字段增加 `REQUIRED`。
* 为现有请求消息增加带 `REQUIRED` 注解的新字段。
* 为之前接受输入的现有字段增加 `OUTPUT_ONLY`。
* 为之前作为输出返回的现有字段增加 `INPUT_ONLY`。
* 为之前被视为可变的现有字段增加 `IMMUTABLE`。
* 从之前作为输入被忽略的现有字段中移除 `OUTPUT_ONLY`。
* 从现有字段中移除 `IDENTIFIER`。

以下变更具有向后兼容性：

* 为现有字段增加 `OPTIONAL`。
* 为现有 `name` 字段增加 `IDENTIFIER`。
* 将现有字段从 `REQUIRED` 改为 `OPTIONAL`。
* 将现有字段从 `OUTPUT_ONLY` 和/或 `IMMUTABLE` 改为 `IDENTIFIER`。
* 从现有字段中移除 `REQUIRED`。
* 从之前在响应中排除的现有字段中移除 `INPUT_ONLY`。
* 从之前被视为不可变的现有字段中移除 `IMMUTABLE`。

## 设计缘由

### 标识符字段行为

资源名称是所有符合规范的资源的主要标识符，创建时不会由用户完整构造。这类字段通常具有 `OUTPUT_ONLY` 字段行为；但当资源本身作为主要请求载荷时，它们又经常被作为主要标识符使用，此时不能视为 `OUTPUT_ONLY`。此外，在标准 Update 等变更请求中，作为主要标识符的资源名称不能原地改变，因此通常具有 `IMMUTABLE` 字段行为。这些相互冲突且依赖上下文的字段行为，说明有必要使用新值专门表达资源名称字段的行为。

### 必需的注解集合

请求消息中使用的字段必须是输入或输出之一。

如果是输出，`OUTPUT_ONLY` 注解就足够了。

如果是输入，字段要么必需，要么可选，因此分别至少应有 `REQUIRED` 或 `OPTIONAL` 注解。只提供 `INPUT_ONLY` 不能表达字段是否必需，所以仍然需要指定 `REQUIRED` 或 `OPTIONAL`。

### 要求字段行为

为每个字段包含字段行为注解，可以更清晰地定义资源的整体行为。明确的字段行为能够改善程序化客户端和用户的理解。

要求使用注解还会迫使 API 作者在最初编写 API 时明确考虑字段行为。

初次编写后修改字段行为，可能导致客户端出现向后不兼容的变化。例如，将可选字段改为必需，会导致 RPC 或[声明式客户端][Declarative client]中的资源方法签名发生向后不兼容的变化。更详细的兼容性指导见[向后兼容性](#向后兼容性)章节。

## 历史

2023 年 5 月，`field_behavior` 变为必需。在此之前，注解经常被省略。高质量客户端生成依赖这些值；此外，在主版本中事后添加或修改某些字段行为值可能向后不兼容。更详细的兼容性指导见[向后兼容性](#向后兼容性)章节。

在 API 编写时要求字段行为，其收益超过不这样做给客户端和 API 用户带来的成本。
