# 请求标识

为特定请求提供由客户生成的唯一标识符，可用于去重并行请求、保证重试安全和审计。最重要的用途是提供幂等性：同一请求重复发送时不会产生额外效果。

## 指导

API **可以**在请求消息中增加 `string request_id` 参数（标准方法也可以），以唯一标识请求。客户端应为每个逻辑请求生成新的随机 ID，并在重试同一请求时复用该 ID；不同逻辑请求不得复用 ID。

服务应在适当时间窗口内保存已处理的 request ID 与结果。重复请求应返回与首次请求等价的结果，不应重新执行副作用；服务无法判断请求是否已完成时，应返回明确错误，而不是盲目执行两次。

```proto
message CreateBookRequest {
  string parent = 1;
  Book book = 2;
  string request_id = 3;
}
```

### 过期的成功响应

request ID 只在服务规定的去重窗口内有效。窗口过期后，重复请求可能被视为新请求；API 必须记录这一语义，客户端不能无限期依赖去重。

## 设计缘由

使用 UUID 等高熵随机 ID 可以极大降低不同请求冲突的概率；服务不得把可预测的连续数字当作跨租户唯一请求标识，也不应把 request ID 当作资源名称。
