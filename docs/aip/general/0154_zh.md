# 资源新鲜度校验

API 经常需要在执行操作前确认客户端和服务端看到的是资源的当前状态。并行更新可能产生竞态，后一个更新会覆盖前一个更新。ETag 允许服务发送基于资源当前内容的校验值，客户端回传后服务即可比较。

## 指导

需要确保客户端使用最新资源时，资源**可以**包含 `string etag`：

```proto
message Book {
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  string title = 2;
  string etag = 3;
}
```

ETag 是不透明值，客户端不得解析或自行计算。服务在资源内容变化时应更新 ETag；如果请求提供 ETag，只有与服务端当前值匹配时操作才应成功，不匹配时必须返回 `ABORTED`。

### 声明式友好资源

声明式友好资源（AIP-128）**必须**提供 ETag，并在 Update、Delete 等变更方法中支持受保护操作，以避免协调工具覆盖其他写入。

### 带请求方法的 ETag

除标准 Update/Delete 外，修改资源的自定义方法也应在请求中接收 ETag。校验应在执行副作用前完成，失败不得部分应用变更。

### 强 ETag 与弱 ETag

强 ETag 表示资源内容的精确版本；只有确实需要精确并发控制时才使用强语义。若服务只能保证表示层或部分内容一致，应在文档中说明弱语义，客户端不应将其当作完整版本号。
