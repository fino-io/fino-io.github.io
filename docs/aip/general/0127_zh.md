# HTTP 与 gRPC 转码

遵循[面向资源的设计][aip-121]的 API 使用 [RPC][rpc] 定义，但面向资源的设计框架也允许将 API 以大体遵循 REST/JSON 约定的形式呈现。这一点很重要，因为它能帮助开发者使用已有知识：现有公开 API 中超过 80% 大体遵循 REST 约定，开发者也已经熟悉这种模式。

## 指导

API **必须**为定义的每个 RPC 提供 HTTP 定义，但无法通过 HTTP/1.1 原生支持的双向流式 RPC 除外。提供双向流式方法时，API **应**同时提供不依赖双向流式传输的替代方法。

### HTTP 方法和路径

使用 Protocol Buffers 时，每个 RPC **必须**使用 `google.api.http` 注解定义 HTTP 方法和路径：

```proto
rpc CreateBook(CreateBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
  };
}

message CreateBookRequest {
  // 将出版该图书的出版商。
  // 使用 HTTP/JSON 时，由于存在 `{parent=publishers/*}` 语法，
  // 该字段会根据 URI 自动填充。
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];

  // 要创建的图书。
  // 使用 HTTP/JSON 时，由于存在 `body: "book"` 语法，
  // 该字段会根据 HTTP 请求体填充。
  Book book = 2 [(google.api.field_behavior) = REQUIRED];

  // 用户指定的图书 ID。
  // 使用 HTTP/JSON 时，该字段会根据查询字符串参数填充，
  // 例如 `?bookId=foo`。这是 URI 或请求体中未包含字段时的兜底方式。
  // 注意，客户端与服务通信时使用 camelCase 格式传递字段名。
  string book_id = 3;
}
```

- 第一个键（本例中的 `post`）对应 HTTP 方法。RPC **可以**使用 `get`、`post`、`patch` 或 `delete`。
  - 如 [AIP-131][]、[AIP-132][]、[AIP-133][]、[AIP-134][] 和 [AIP-135][] 所述，RPC **必须**为每个标准方法使用规定的 HTTP 动词。
  - 如 [AIP-136][] 所述，RPC **应**为自定义方法使用规定的 HTTP 动词。
  - RPC **不应**使用 `put` 或 `custom`。
- 对应的值表示 URI。
  - URI **必须**使用 `{foo=bar/*}` 语法表示应填充到请求 proto 中的变量。提取[资源名称][aip-122]时，变量**必须**包含完整资源名称，而不只是 ID 片段。
  - URI **可以**在变量名中使用嵌套字段。（此外，AIP-134 要求 Update 请求采用这一方式。）
  - URI **必须**使用 `*` 表示 ID 片段；它匹配除 `/` 之外的所有 URI 安全字符。如果必须匹配 `/`，URI **可以**在 URI 的最后一个片段使用 `**`。
- `body` 键定义请求中的哪个单一顶层字段将作为 HTTP 请求体发送。如果请求体是 `*`，表示请求对象本身就是 HTTP 请求体。请求体按照 Protocol Buffers 的标准 [JSON 编码][json encoding]编码。
  - 使用 HTTP `GET` 或 `DELETE` 动词的 RPC **不得**定义 `body`。
  - Create（[AIP-133][]）和 Update（[AIP-134][]）请求**必须**使用规定的 `body`。
  - 自定义方法（[AIP-136][]）**应**使用规定的 `body`。
  - `body` **不得**包含嵌套字段（也不得使用 `.` 字符）。
  - `body` **不得**与 URI 参数相同。
  - `body` **不得**是 `repeated` 字段。
  - 除非出于向后兼容原因，否则字段**不应**使用 `json_name` 注解修改其 JSON 中的字段名。

**注意：** 双向流式 RPC 不应包含 `google.api.http` 注解。如果可行，服务**应**提供非流式等价 RPC。

### 多个 URI 绑定

有时，一个 RPC 需要对应多个 URI：

```proto
rpc CreateBook(CreateBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
    additional_bindings: {
      post: "/v1/{parent=authors/*}/books"
      body: "book"
    }
    additional_bindings: {
      post: "/v1/books"
      body: "book"
    }
  };
}
```

- RPC **可以**定义任意数量的附加绑定。其结构与 `google.api.http` 注解相同（事实上，这是递归引用）。
- RPC **不得**在附加绑定中再定义附加绑定。
- 顶层注解和每个附加绑定中的 `body` 子句**必须**相同。
