# 软删除

支持恢复的主要原因是从误操作中恢复。支持 undelete 的服务可以让用户找回意外删除的资源。

## 指导

API **可以**支持恢复。支持恢复时，Delete **必须**只把资源标记为已删除，而不能立即从系统中彻底移除；此时 Delete **应**返回更新后的资源，而不是 `google.protobuf.Empty`。

资源**应**包含 AIP-148 描述的 `delete_time` 和 `purge_time`，并**应**包含一个表示删除状态的字段（通常为 `state`）。软删除资源在 Get 时通常仍可返回，但 List 默认不应包含，除非请求提供 `show_deleted`。

### 恢复

恢复应使用名为 `Undelete` 的自定义方法，并接收资源 `name`。只有处于可恢复状态的资源才能恢复；恢复后资源应回到可正常 Get/List 的状态。恢复必须遵循权限、ETag 和一致性校验。

```proto
rpc UndeleteBook(UndeleteBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/books/*}:undelete"
    body: "*"
  };
}
```

### 恢复请求消息

请求**必须**包含 `name`，且应标注为必填并引用资源类型；可以包含 `etag` 或其他由 AIP 明确说明的保护字段，不应包含任意必填字段。

### 长时运行的恢复

恢复可能耗时时，Undelete **应**返回长时运行 Operation，并将 `response_type` 设置为资源类型、`metadata_type` 设置为操作元数据类型。

### 永久清除

彻底清除资源应使用名为 `Expunge` 的自定义方法。Expunge 不可逆，必须明确告知调用方，并且只能作用于已经软删除且达到保留期限的资源；服务可以允许管理员提前清除，但应使用更高权限。

### 长时运行的清除

清除大量或复杂资源时应使用长时运行 Operation；完成后不得再返回被清除的资源。

### 清除请求消息

请求**必须**包含资源 `name`，可以包含 `etag` 或 `force` 等显式保护选项。服务应避免允许模糊的批量清除。

### List 与 Get

List 默认不得返回软删除资源，应提供 `show_deleted`；Get 可以返回已删除资源，以便用户读取删除时间、清除时间和恢复状态。已永久清除的资源必须返回 `NOT_FOUND`。

### 声明式友好资源

声明式友好资源应提供删除时间、清除时间、状态和 ETag，并支持安全恢复；声明式工具必须能区分“服务端已删除”与“资源不存在”。

### 错误

无权访问时应返回 `PERMISSION_DENIED`；资源不存在时返回 `NOT_FOUND`；状态不允许恢复或清除时返回 `FAILED_PRECONDITION`。错误不能泄露已删除但调用方无权访问的资源信息。
