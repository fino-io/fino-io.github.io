# 导入与导出

许多用户需要将数据载入 API，或取出已有数据；企业用户尤其关注供应商锁定。API **可以**支持导入、导出操作，它们可以创建多个新资源，也可以向单个资源填充数据。

## 指导

### 多个资源

服务**可以**支持多个资源的导入和导出，并**应**使用常见模式：以专用请求消息描述来源或目标，以长时运行 Operation 表示进度和结果，并在完成后提供成功、失败和跳过项目的统计。

```proto
rpc ImportBooks(ImportBooksRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books:import"
    body: "*"
  };
}
```

导入应明确如何处理重复资源（失败、跳过或更新），导出应定义格式、版本、权限和分页/分片方式。大数据集应使用用户可访问的外部存储 URI，而不是把全部数据放入 RPC。

### 单个资源的数据

如果导入或导出的是单个资源的一部分数据，可以使用资源上的自定义方法；方法仍应明确数据格式、覆盖/合并语义和失败处理。导入不应绕过正常资源校验或授权。

### 请求对象

请求消息应包含父资源或目标资源、数据源/目标、格式以及必要的校验选项。敏感数据 URI 不应出现在错误消息中；服务应在 Operation metadata 中提供可操作的进度信息。

### 内联来源

数据量较小且有明确大小上限时，可以在请求中内联数据；服务必须记录大小限制，并拒绝超过限制的请求。对大数据使用内联传输会造成超时和内存压力，不应作为默认方案。

### 部分失败

批量导入导出应允许部分成功，并在结果中报告每个项目的错误。整体 Operation 只有在所有项目成功时才应表示完全成功；调用方应能区分可重试错误、永久错误和已成功项目。
