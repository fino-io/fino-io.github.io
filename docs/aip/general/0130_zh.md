# 方法

API 由一个或多个方法组成，每个方法代表服务可以代表消费者执行的一项具体操作。

## 指导

### 方法类别

以下列出多种方法类别。它们通常按方法所操作的对象（例如集合或资源）归组。

| 类别名称 | 相关 AIP | [声明式客户端][]集成 | CLI / UI 集成 | SDK 集成 |
| --- | --- | --- | --- | --- |
| *标准方法* |  |  |  |  |
| **标准集合方法**：操作资源集合（List 或 Create）。 | [AIP-121][]、[AIP-132][]、[AIP-133][] | 可自动化 | 可自动化 | 可自动化 |
| **标准资源方法**：获取或变更单个资源（Get、Update、Delete）。 | [AIP-121][]、[AIP-131][]、[AIP-134][]、[AIP-135][] | 可自动化 | 可自动化 | 可自动化 |
| **批量资源方法**：按名称在集合中获取或变更多个资源。 | [AIP-231][]、[AIP-233][]、[AIP-234][]、[AIP-235][] | 可用于优化查询 | 可自动化 | 可自动化 |
| **聚合列表方法**：跨多个集合获取或变更多个同类型资源。 | [AIP-159][] | 不实用，也无法自动化 | 可自动化 | 可自动化 |
| *自定义获取方法* |  |  |  |  |
| **自定义集合获取方法**：获取无法用标准方法表达的集合信息。 | [AIP-136][] | 手写 | 可自动化 | 可自动化 |
| **自定义资源获取方法**：获取无法用标准方法表达的单个资源信息。 | [AIP-136][] | 手写 | 可自动化 | 可自动化 |
| *自定义变更方法* |  |  |  |  |
| **备份资源**：存储资源在某一时间点的副本。 | [AIP-162][] | 不使用或手写 | 可自动化 | 可自动化 |
| **恢复资源**：将资源设置为某一时间点的版本。 | [AIP-162][] | 不使用或手写 | 可自动化 | 可自动化 |
| **重命名资源**：在保留配置和数据的同时修改资源名称或 ID。 | [AIP-136][] | 不使用或手写 | 可自动化 | 可自动化 |
| **自定义集合变更方法**：引用集合并执行命令式操作，可能变更该集合中的一个或多个资源，且无法轻易通过标准方法实现（例如状态转换）。 | [AIP-136][] | 不使用或手写 | 可自动化 | 可自动化 |
| **自定义资源变更方法**：对资源执行命令式操作，以标准方法无法实现的方式变更资源（例如状态转换）。 | [AIP-136][] | 不使用或手写 | 可自动化 | 可自动化 |
| *其他自定义方法* |  |  |  |  |
| **无状态方法**：对 API 中任何数据都没有永久影响的方法（例如翻译文本）。 | [AIP-136][] | 不使用或手写 | 可自动化 | 可自动化 |
| *以上都不适用* |  |  |  |  |
| **流式方法**：通过客户端流、服务器流或双向流通信的方法。 |  | 手写 | 手写 | 可自动化 |

### 选择方法类别

设计方法时，API 作者应按以下顺序从已定义的类别中选择：

1. 标准方法（用于集合和资源）
1. 标准批量方法或聚合方法
1. 自定义方法（用于集合、资源或无状态操作）
1. 流式方法

## 设计缘由

面向资源的标准方法和自定义方法应优先考虑，因为它们可以在最广泛的客户端（声明式客户端、CLI、UI 等）中表达，并提供最统一的体验，让用户能够将一个 API 的知识应用到另一个 API。

如果标准方法不适用，则挂载到资源或集合上的自定义方法提供较低但仍然有价值的一致性，帮助用户判断操作的作用范围，以及读取哪些对象的配置来决定如何执行操作。尽管可变更的自定义方法还不够统一，无法与纯面向资源的客户端（例如[声明式客户端][]）自动集成，但它们仍是一种 CLI、UI 和 SDK 可以轻松识别的模式。

如果 API 完全无法采用面向资源的方式表达，那么其操作会落入缺乏统一性的类别，除 SDK 外的任何客户端都难以建模这种操作。由于用户无法依赖对相似 API 的知识，且与多个客户端的集成很可能必须手写，因此应最后选择此类别。
