# 字段掩码

更新资源时，调用方往往需要明确哪些字段被修改，以便服务忽略请求中的其他值。字段掩码是结构化表达方式，字段类型**必须**是 `google.protobuf.FieldMask`，并且通常用于 Update（AIP-134）。

## 指导

掩码**必须**始终相对于资源，而不是请求消息；例如 `book.title` 应写成 `title`。掩码中的字段必须是可更新字段，服务应拒绝未知、只读或不可变字段。

### 读写一致性

Update 请求中的资源内容和掩码共同决定修改范围。掩码列出的字段即使在请求中为空，也应按 API 约定清空；掩码未列出的字段不得被修改。省略掩码时应遵循 AIP-134 的隐含掩码语义。

### 指定字段

字段名使用 `snake_case`，嵌套字段用 `.` 分隔；重复字段和 map 字段的更新语义必须明确。服务可以规范化顺序和去重，但不能改变字段集合。

### Map 字段

对 map 字段使用字段名通常表示替换整个 map；如果需要更新单个键，应定义明确的专用操作或文档化键级语义，而不能让客户端猜测。

### 通配符

特殊值 `*` 表示所有可更新字段，但调用方应谨慎使用：服务未来新增字段时，旧客户端使用 `*` 可能意外覆盖新字段。显式列出字段通常更安全。

### 仅输出字段

仅输出字段不得出现在更新掩码中；如果出现，服务应返回 `INVALID_ARGUMENT`。服务生成字段应在更新后按其正常规则计算。

### 无效掩码条目

未知字段、重复冲突路径、只读字段或不允许更新的父字段都应导致明确错误。错误消息应指出无效路径，帮助调用方修正请求。
