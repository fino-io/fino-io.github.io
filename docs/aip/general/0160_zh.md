# 过滤

List 方法通常需要只返回用户关心的资源。过滤需求经常演进，因此 API **应**使用面向非技术用户的字符串语法，而不是为每种需求定义固定请求结构。过滤语法可以借用口语表达，不必完全遵循代码中的常见形式。

## 指导

API **可以**在 List 或类似方法中提供 `string filter` 字段。服务必须记录支持的语法、字段、运算符和默认行为；未知字段或无效表达式应返回 `INVALID_ARGUMENT`，不能静默忽略。

### 字面量

支持字符串、数字、布尔值、时间戳和枚举等字面量，并记录转义规则。字符串通常使用双引号；字段名和关键字的大小写语义必须明确。

### 逻辑运算符

应支持 `AND`、`OR` 和括号以组合条件；`AND` 优先级应高于 `OR`，但调用方应使用括号表达复杂意图。空过滤器通常表示不过滤。

### 否定运算符

可以支持 `NOT` 或 `!=`。服务必须定义空值、缺失字段和否定集合的语义，避免用户把“字段不存在”误解为“字段不等于某值”。

### 比较运算符

常见运算符包括 `=`、`!=`、`<`、`<=`、`>`、`>=`。比较应使用字段类型的自然语义；时间按时间比较，数字按数值比较，字符串按文档规定的排序比较。

### 遍历运算符

嵌套消息字段可以使用 `.` 遍历，例如 `author.name = "..."`。对重复消息的遍历语义必须明确：通常表示至少一个元素满足条件。

### Has 运算符

可以提供 `has(field)` 判断字段是否存在，尤其适用于 proto3 optional、消息字段和未设置值。服务应区分未设置、默认值和空集合。

### 函数

只有有明确需求时才增加函数，例如时间范围或字符串前缀函数；每个函数必须说明参数类型、返回值、大小写和时区语义。

### 限制

过滤器可能消耗大量 CPU 或触发昂贵索引。服务可以限制长度、嵌套深度、复杂度和执行时间，并在文档中说明限制；不应允许过滤器访问未授权字段。

### 校验

服务应在执行查询前解析并校验过滤器，错误应指出可定位的语法问题。过滤器语义属于 API 契约，新增运算符可以是兼容增强，但改变已有表达式含义是破坏性变更。
