# 敏感字段

API 有时需要收集由底层服务存储、但写入后不应再次读取的敏感信息，例如私有加密密钥。此类信息需要特别设计请求和响应中的表示方式。

## 指导

如果敏感信息是资源存在的必要条件，**应**将其作为[仅输入字段][input-only]接收，并且不提供对应的输出字段。资源存在本身即可让用户推断敏感信息已被存储：

```proto
message SelfManagedKeypair {
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  bytes public_key = 2;
  bytes private_key = 3 [(google.api.field_behavior) = INPUT_ONLY];
}
```

如果敏感信息在资源中是可选的，**应**使用带 `_set` 后缀的[仅输出][output-only]布尔字段说明其是否存在：

```proto
message Integration {
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  string uri = 2;
  string shared_secret = 3 [(google.api.field_behavior) = INPUT_ONLY];
  bool shared_secret_set = 4 [(google.api.field_behavior) = OUTPUT_ONLY];
}
```

如果需要识别敏感信息但不能完整读回，可以用同类型且带 `obfuscated_` 前缀的仅输出字段代替 `_set`；具体混淆方式不在本 AIP 范围内，例如 `ada@example.com` 可显示为 `a**@e*****e.com`。
