# 枚举

字段只接受或提供一组离散且有限的值是很常见的。在这种情况下，使用枚举（通常简称为“enum”）可以清晰地表达允许的值集合。

## 指导

对于预期很少变化的值集合，API **可以**暴露枚举对象：

```proto
// 图书的表示。
message Book {
  // 其他字段……

  // 图书可能采用的出版形式。
  enum Format {
    // 默认值。此值未使用。
    FORMAT_UNSPECIFIED = 0;

    // 印刷版，精装。
    HARDBACK = 1;

    // 印刷版，平装。
    PAPERBACK = 2;

    // 电子书格式。
    EBOOK = 3;

    // 有声读物。
    AUDIOBOOK = 4;
  }

  // 图书的出版形式。
  Format format = 99;

  // 其他字段……
}
```

- 所有枚举值**必须**使用 `UPPER_SNAKE_CASE`。
- 枚举的第一个值**应**使用枚举名称加 `_UNSPECIFIED` 后缀。
  - 如果存在明确有用的零值，则此规则例外。特别是，如果枚举需要提供 `UNKNOWN`，通常让它成为零值比同时存在两个值更清晰、更有用。为避免枚举值名称冲突，`UNKNOWN` 值**可以**像通常做法一样加上枚举名称前缀。
- 只在一个消息中使用的枚举**应**嵌套在该消息中。此时，枚举**应**紧邻其使用位置之前声明。
  - 这类嵌套枚举定义的非零值**不应**带枚举名称前缀。否则用户通常需要在代码中写 `MyState.MYSTATE_ACTIVE`，显得不必要地冗长。
- 会被多个消息使用的枚举**应**在包级别定义，并且**应**定义在 proto 文件底部（参见 [AIP-191][]）。
  - 某些语言（包括 C++）会将枚举值提升到父命名空间，从而可能导致同一 proto 包中不同枚举的值发生冲突。为避免共享值，API **应**为包级枚举值加上枚举名称前缀。
- 枚举**应**说明其值集合是否冻结，或者预计未来是否会增加值。

### 何时使用枚举

在许多情况下，枚举比字符串或布尔值更易访问和阅读，但枚举发生变化时会增加开销。因此，枚举**应**很少增加新值。虽然“很少”的定义可能因使用场景而异，但一个好的经验法则是不超过每年一次。对于频繁变化的枚举，API **应**改用字符串，并记录其格式。

此外，如果存在广泛采用的竞争性标准表示（例如[语言代码][bcp-47]或[媒体类型][media types]），则**不应**使用枚举。

**注意：** 如果某个枚举值需要在多个 API 之间共享，可以使用枚举，但枚举值与对应整数之间的分配关系**必须**保持一致。

### 替代方案

对于允许值集合频繁变化的枚举值，API **应**改用 `string` 字段，并且**必须**记录允许的值。包含枚举值的字符串字段**应**使用 `kebab-case` 表示其值。

对于存在广泛采用的竞争性标准表示的枚举值（通常但不一定是字符串），**应**使用该标准表示。即使只允许其中很小的值子集，也应如此，因为这种情况下使用枚举，多个 API 组合使用时往往会导致令人沮丧的查找表。

在明确不需要进一步灵活性的情况下，**可以**使用布尔字段。默认值**必须**是 `false`。

**注意：** 使用 Protocol Buffers 时，无法区分 `false` 和未设置。如果这是必要条件，枚举可能是更好的设计选择（不过也可以使用 `google.protobuf.BoolValue`）。
