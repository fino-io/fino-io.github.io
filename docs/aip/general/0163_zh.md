# 变更校验

用户有时希望在真正执行变更前验证其结果，例如预估新增服务器对集群规模、成本和下游系统的影响。

## 指导

API **可以**提供只校验、不执行请求的选项，并返回与实际执行时相同的状态码、响应头和响应体。请求消息**应**包含 `bool validate_only`：

```proto
message ReviewBookRequest {
  string name = 1;
  bool validate_only = 2;
}
```

当 `validate_only` 为 `true` 时，服务不得持久化资源、触发副作用或产生计费；但应执行权限、格式、配额、依赖和业务规则校验。验证结果应尽可能与真实执行一致，不能把“验证成功”解释为之后执行必然成功，因为状态可能在两次请求之间变化。

### 声明式友好资源

声明式工具可以先执行校验再执行变更，但服务仍应在真实请求中再次验证，不能把 validate-only 结果当作锁或预留。
