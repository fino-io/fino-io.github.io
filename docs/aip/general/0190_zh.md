# 命名约定

Google API 的名称应让开发者长期、跨 API 地理解。所有接口、资源、集合、方法和消息名称**应**直白、直观且一致。由于许多开发者把英语作为第二语言，名称应优先使用简单、常见、可翻译的词。

## 指导

资源名、集合名和字段名应遵循 AIP-122、AIP-140 等专门指导。避免无意义缩写、俚语、品牌内部术语、双关语和同义词混用。名称应表达 API 中的概念，而不是底层数据库表或实现细节。

### 接口名称

服务接口名称**应**使用清晰的产品或领域名，并以 `Service` 结尾（如 `LibraryService`）。同一服务中的资源、方法和消息应使用一致的词根。

### 方法名称

标准方法使用 `Get`、`List`、`Create`、`Update`、`Delete`；自定义方法应使用动词加名词，避免介词和 `Async`。方法名称应明确操作对象，不应把查询条件编码进名称。

### 消息名称

消息名称**应**使用 PascalCase 的名词单数形式。请求和响应分别以 `Request`、`Response` 结尾；不要在消息名中重复服务名或包名已经表达的上下文。

#### 请求和响应消息

一个 RPC 的请求和响应消息应有稳定、可预测的名称。响应不是请求消息的镜像时，也应使用能表达结果语义的名词，而不是 `Result`、`Data` 等过于宽泛的名称。
