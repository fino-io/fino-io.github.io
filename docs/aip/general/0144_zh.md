# 重复字段

在 API 中表示列表比表面上更复杂：用户可能需要原地修改列表，单个资源中的长序列也会带来分页问题。

## 指导

资源**可以**在适当时使用重复字段。

```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  repeated string authors = 2;
}
```

### 标量与消息

重复标量适合简单值列表；如果列表项需要稳定身份、独立注释或额外属性，应使用重复消息。重复字段**应**使用复数名称。

### 更新策略

更新重复字段时必须明确列表语义。字段掩码中指定重复字段，通常表示用请求中的完整列表替换现有列表；如果需要增删单个元素、保持元素顺序或按元素合并，应定义清晰的自定义方法或专用消息，而不要让 Update 的隐含语义猜测用户意图。

需要在单个资源中返回超长列表时，应考虑将元素建模为子资源并使用 List；这样既可以分页，也能对元素单独授权和更新。

### 请求消息

API **不应**把同一列表同时建模为重复字段和单独的集合资源；应根据数据规模、生命周期、授权和更新方式选择一种主模型。对列表的过滤、排序和分页语义应遵循对应 AIP。
