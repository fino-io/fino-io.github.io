# 自动重试配置

RPC 有时会失败，客户端需要知道重复调用是否安全。跨 API 一致使用状态码，客户端才能正确响应失败。

## 指导

客户端**应**自动重试：重复运行不会造成非预期状态变化、操作非事务性且 RPC 是 unary 的请求。事务请求**不应**自动重试，而应由应用层从整个事务块开始重试。重复运行会造成非预期状态变化的请求**不应**自动重试。

### 可重试错误码

通常可以重试 `UNAVAILABLE`、`DEADLINE_EXCEEDED`，以及明确表示瞬时资源不足的错误。重试必须使用退避和抖动，并设置总时限；不能在服务持续不可用时形成请求风暴。

### 不可重试错误码

`INVALID_ARGUMENT`、`PERMISSION_DENIED`、`UNAUTHENTICATED`、`NOT_FOUND`、`ALREADY_EXISTS` 等表示请求或权限问题的错误通常不可通过原样重试解决。客户端应修正请求、刷新凭证或向用户报告。

### 一般不可重试的错误

`FAILED_PRECONDITION`、`ABORTED`、`OUT_OF_RANGE` 和 `RESOURCE_EXHAUSTED` 是否重试取决于具体语义；服务应在文档中说明。带 request ID 的幂等写操作可以安全重试，非幂等写操作必须先确认不会重复副作用。
