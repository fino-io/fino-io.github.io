# 通用组件

如 [AIP-215][] 所述，除了使用面向多个 API 的“通用组件”包之外，API **必须**自包含。

通用组件包有两类：

- 组织专用通用组件，涵盖组织专用概念，例如 Maps 中的“视口”。
- 全局通用组件，即通用（不特定于某个领域）的组件，例如“时间戳”或“邮政地址”。

在多个 API 之间安全共享单一表示的情况下，通用组件可以让客户端更容易与这些 API 交互。例如，可以只编写一次特定概念的客户端代码，也可以直接在一个 API 的响应中使用消息作为另一个 API 的请求，而不必笨拙地复制消息。

不过，这一收益伴随着显著的限制，不应轻率尝试。

需要注意的是，即使组件所属的*领域*是通用的，组件的要求也可能是组织专用的。例如，一些组织可能对金融值的表示有特殊要求，从而产生多个面向金融的组织专用通用组件；因为任何全局通用组件要么无法满足组织专用要求，要么对一般使用来说过于复杂。

## 指导

- 组织范围通用组件包**必须**以 `.type` 结尾，例如 `google.geo.type` 或 `google.shopping.type`。
- 组织在创建新的组织范围通用组件包前**必须**咨询 API 设计团队。
- 组织范围通用组件包**必须**发布在 [`googleapis` 仓库](https://github.com/googleapis/googleapis)中。
- 创建并发布新组织范围通用组件包的组织**必须**更新本 AIP，将该包加入[下方列表](#现有组织专用通用组件包)。
- 组织**不得**在组织专用通用组件包中定义通用组件，而应优先使用全局通用组件。
- 通用组件**不得**从组织专用通用组件包“移动”（即从一个包删除后添加到另一个包）到全局通用组件包，反之亦然。
  - 如果发现某个组件的适用范围比最初预期更广，则**可以**将其从组织专用通用组件包复制到全局通用组件包，但不得删除原组件。
- **不应**向现有消息添加字段。
- **不应**向现有枚举添加值。
- **不得**从现有消息中删除字段。
- **不得**从现有枚举中删除值。
- 文档**可以**澄清，但**不应**改变现有值的含义，包括任何给定消息或消息集合的有效性。
- **可以**向通用组件包添加新的 proto 消息和枚举。
  - API 团队在 API 中使用新消息和枚举前，**应**为其传播到客户端预留足够时间。字段的变更可能需要一段时间才能通过发布传播到客户端库和其他表面。
  - 鉴于上述限制，API 团队在添加新消息或枚举前，**应**在组织内部广泛征求意见，理想情况下还应咨询 API 设计团队。

## 现有全局通用组件

公共 API proto **可以**安全导入的全局通用组件如下：

- [`google.api.*`](https://github.com/googleapis/googleapis/blob/master/google/api)（但不包括 `google.api` 的子包）
- [`google.longrunning.Operation`](https://github.com/googleapis/googleapis/blob/master/google/longrunning/operations.proto)
- [`google.protobuf.*`](https://github.com/protocolbuffers/protobuf/tree/master/src/google/protobuf)
- [`google.rpc.*`](https://github.com/googleapis/googleapis/blob/master/google/rpc/)
- [`google.type.*`][type]

需要注意，一些通用组件可能包含仅供内部使用的字段。API **通常应**只依赖已经[发布到开源代码库][released open source]的字段。

Google API **也可以**导入 [`google.iam.v1.*`][iam]，它提供了 Google 各处使用的 IAM 消息。

**注意：** 许多 API 也会出于内部使用目的导入其他包中的组件（例如应用可见性标签，或向内部基础设施提供指令）。只要公共组件不包含此类引用，这就是可以接受的。

### Protobuf 类型

`google.protobuf` 包有些特殊：它随 Protocol Buffers 本身一起发布，而不是随 API 工具发布。（对于大多数 API 设计者来说，这属于实现细节。）

该包包含一小组用于表示常见编程语言构造的类型：

- [`google.protobuf.Duration`][duration]：具有纳秒级精度的时长。对于适用的语言，protobuf 运行时提供与该语言原生时长对象相互转换的辅助函数（例如 Python 的 [`timedelta`][timedelta]）。
- [`google.protobuf.Struct`][struct]：类似 JSON 的结构（由原始类型、列表和其他字典组成的字典）。protobuf 运行时在大多数语言中提供将结构对象与 JSON 相互转换的辅助函数。
- [`google.protobuf.Timestamp`][timestamp]：具有纳秒级精度的时间戳。对于适用的语言，protobuf 运行时提供与该语言原生时间戳对象相互转换的辅助函数（例如 Python 的 [`datetime`][datetime]）。

### API 类型

`google.type` 包提供了一套可用于表示 API 中常见概念的类型“标准库”。虽然该包会不时增加类型，且权威列表始终以[代码][type]为准，但以下类型值得特别说明：

- [`google.type.Color`][color]：RGB 或 RGBA 颜色。
- [`google.type.Date`][date]：不包含时间或时区部分的日历日期。
- [`google.type.DayOfWeek`][day_of_week]：星期几，不包含其他日期、时间或时区部分。
- [`google.type.LatLng`][lat_lng]：地理坐标。
- [`google.type.Money`][money]：货币。
- [`google.type.PostalAddress`][postal_address]：大多数国家的邮政地址。
- [`google.type.TimeOfDay`][time_of_day]：墙上时钟时间，不包含日期或时区部分。

### 添加到通用 proto

有时，向这些包中添加 proto，或将 proto 加入通用可用 proto 列表，可能很有用。要这样做，请在 GitHub 上的 AIP 仓库[提交 issue][open an issue]，并说明上面的指导。

## 现有组织专用通用组件包

以下组织专用通用组件包已经存在，并符合上面的指导：

- [`google.apps.script.type`](https://github.com/googleapis/googleapis/tree/master/google/apps/script/type)：Google Apps Script 的通用组件包。
- [`google.geo.type`](https://github.com/googleapis/googleapis/tree/master/google/geo/type)：Google Maps 和 Geo 组织的通用组件包。
- [`google.actions.type`](https://github.com/googleapis/googleapis/tree/master/google/actions/type)：Actions on Google API 的通用组件包。
- [`google.shopping.type`](https://github.com/googleapis/googleapis/tree/master/google/shopping/type)：Google Shopping 的通用组件包。

## 不符合规范的通用组件包

以下通用组件包已经存在，但不符合上述指导，也不构成未来创建此类包的先例。

- [`google.cloud.common`](https://github.com/googleapis/googleapis/tree/master/google/cloud/common)：不符合包名必须以 `.type` 结尾的要求。（否则它是可以接受的，应视为 Cloud 通用组件包。）
- [`google.logging.type`](https://github.com/googleapis/googleapis/tree/master/google/logging/type)：看起来是 API 专用的，尽管被多个 API 使用；其中一些内容可能应当是全局组件，或位于 Cloud 通用组件包中。
- [`google.cloud.workflows.type`](https://github.com/googleapis/googleapis/tree/master/google/cloud/workflows/type)：API 专用类型。
- [`google.cloud.oslogin.common`](https://github.com/googleapis/googleapis/tree/master/google/cloud/oslogin/common)：API 专用类型，且名称不符合规范。
- [`google.identity.accesscontextmanager.type`](https://github.com/googleapis/googleapis/tree/master/google/identity/accesscontextmanager/type)：API 专用类型。
- [`google.networking.trafficdirector.type`](https://github.com/googleapis/googleapis/tree/master/google/networking/trafficdirector/type)：API 专用类型。

## 设计缘由

通用组件实际上没有版本：API 在定义和实现上彼此独立演进。在特定 API 中，增加字段这样的变更具有向后兼容性且可预测，API 团队可以确保服务器实现先于 API 定义发布。相比之下，通用组件的变更实际上会对所有 API 立即可用，即使大多数 API 实现没有考虑该变更。

新增消息或枚举具有向后兼容性，因为它不会影响那些从同一通用组件包导入其他消息或枚举的现有 API。

全局通用组件必须咨询 API 设计团队；组织专用通用组件则建议咨询，因为“通用”和“组织专用”的边界比较模糊。某些通用*概念*可能具有组织专用的使用场景，并通过组件显现出来。
