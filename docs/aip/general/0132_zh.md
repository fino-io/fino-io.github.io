# 标准方法：List

在许多 API 中，通常向集合 URI（例如 `/v1/publishers/1/books`）发送 `GET` 请求，以获取该集合中的资源列表。

面向资源的设计（[AIP-121][]）通过 `List` 方法遵循这一模式：RPC 接收父集合以及可能的其他参数，并返回与输入匹配的资源列表。

## 指导

除非资源是[单例资源][singleton]，API **必须**为资源提供 `List` 方法。List 方法用于返回有限集合中的数据；除非支持[跨集合读取][reading across collections]，该集合通常对应单个父资源。

```proto
rpc ListBooks(ListBooksRequest) returns (ListBooksResponse) {
  option (google.api.http) = {
    get: "/v1/{parent=publishers/*}/books"
  };
  option (google.api.method_signature) = "parent";
}
```

- RPC 名称**必须**以 `List` 开头，其余部分**应**使用被列出资源的复数形式。
- 请求和响应消息**必须**与 RPC 名称匹配，并分别以 `Request`、`Response` 结尾。
- HTTP 动词**必须**为 `GET`。
- 被列出的集合**应**映射到 URI 路径；父资源**应**命名为 `parent`，并作为路径中的唯一变量。集合标识符（上例中的 `books`）**必须**是字面量。
- `google.api.http` 注解中**必须**省略 `body`。
- 非顶层资源**应**有一个值为 `"parent"` 的方法签名；顶层资源可以没有方法签名，或使用值为 `""` 的方法签名。

### 请求消息

```proto
message ListBooksRequest {
  // 拥有此图书集合的父资源。
  // 格式：publishers/{publisher}
  string parent = 1 [
    (google.api.field_behavior) = REQUIRED,
    (google.api.resource_reference) = {
      child_type: "library.googleapis.com/Book"
    }];
  int32 page_size = 2;
  string page_token = 3;
}
```

- 除非列出的是顶层资源，否则**必须**包含 `parent` 字段；该字段**应**标注为必填，并**必须**标识被列出资源的类型。
- 所有 List 请求**必须**包含 `page_size` 和 `page_token` 字段，以支持分页，详见 [AIP-158][]。
  - `page_size` 注释**应**说明默认值和最大值；超过最大值时服务**应**将其限制为最大值，负数或其他无效值**必须**返回 `INVALID_ARGUMENT`。
- 可以加入 `filter`、`order_by` 等适用于 List 的通用模式字段，但不得加入未由本 AIP 或其他 AIP 说明的必填字段。

**注意：** 对于有权成功调用 List 的用户，List 方法**应**返回相同结果；Search 方法不受此要求严格约束。

### 响应消息

```proto
message ListBooksResponse {
  repeated Book books = 1;
  string next_page_token = 2;
}
```

- 响应**必须**包含一个与返回资源对应的 repeated 字段，除其他 AIP 另有说明外**不应**包含其他 repeated 字段。
- `next_page_token` **必须**出现在所有 List 响应中：存在后续页面时必须设置，最后一页不得设置。
- 可以包含 `int32` 或 `int64` 类型的 `total_size` 字段。该值可以是估计值，但必须明确说明；使用过滤时，应表示过滤后的集合大小。

### 排序

List 方法**可以**支持排序；支持时请求消息**应**包含 `string order_by`。值应为以逗号分隔的字段列表，例如 `"foo,bar"`；默认升序，字段后追加 ` desc` 表示降序。空格无意义，子字段使用 `.` 表示。排序通常应使用字段类型的自然比较器；若采用其他顺序，必须在字段定义中说明。只有确有需求时才应加入排序，因为后续可以增加，但删除排序支持会造成破坏性变更。

### 过滤

List 方法**可以**支持过滤；支持时请求消息**应**包含 `string filter` 字段，详见 AIP-160。只有确有需求时才应加入过滤，因为后续可以增加，但删除过滤支持会造成破坏性变更。

### 软删除资源

支持[软删除][soft delete]的 API 默认**不应**在 List 结果中包含已删除资源；应提供 `bool show_deleted` 字段，使调用方能够选择包含这些资源。

### 错误

请参阅[错误][errors]，尤其是[何时使用 PERMISSION_DENIED 和 NOT_FOUND][permission-denied]。
