# 策略预览

策略是一种资源，它提供允许或拒绝访问其他资源的规则。通常，策略的结果可以评估为一组具体结果。

未经适当校验就修改策略，可能产生意外后果，严重影响客户的整体基础设施配置。为了安全地更新资源，通过策略发布 API 测试这些变更会很有帮助。

预览是策略资源的发布安全机制，让客户可以在变更正式生效前，针对生产流量验证提议变更的效果。策略针对流量评估的结果会记录到日志中，从而为客户提供测试变更正确性所需的数据。

防火墙策略就是适合预览的例子。可以针对流量评估新配置，观察哪些 IP 会被允许或拒绝。这些数据可以帮助客户决定是否将提议的变更提升为正式配置。

预览策略的预期流程如下：

1. 用户创建包含新策略配置的实验，该配置用于替换正式策略。
2. 用户使用 `startPreview` 方法开始生成日志，比较正式策略和实验策略针对实时流量的评估结果。
3. 用户检查日志，判断实验是否产生预期结果。
4. 用户使用 `commit` 方法将实验提升为正式配置。

## 指导

### 非目标

本提案仅针对策略发布的安全机制。非策略资源的安全发布不在范围内。

### 实验

要预览的策略新配置以策略下的嵌套集合形式存储。这些嵌套集合称为实验。

下文始终使用一个假设的 `Policy` 策略资源。它的资源名称模式如下：

`projects/{project}/locations/{location}/policies/{policy}`

用于预览或其他安全发布实践的资源实验版本，使用新的资源类型作为 `Policy` 下的嵌套集合表示。资源类型**必须**遵循 *RegularResourceType*`Experiment` 的命名约定。

实验集合使用以下模式：

`projects/{project}/locations/{location}/policies/{policy}/experiments/{experiment}`

用于表示实验的 proto **必须**包含以下内容：

1. 资源所需的顶层字段，例如 `name` 和 `etag`。
2. 正在测试的策略消息本身。
3. `preview_metadata` 字段，其中包含预览某种具体资源类型实验所需的元数据。

```proto
message PolicyExperiment {

  // google.api.resource、name 以及其他注解和字段

  // 策略实验。此 Policy 用于预览变更效果，但不会影响实时流量。
  Policy policy = 2;

  // 与此策略实验关联的元数据。
  PolicyPreviewMetadata preview_metadata = 3
      [(google.api.field_behavior) = OUTPUT_ONLY];

  // 允许客户端存储少量任意数据。
  map<string, string> annotations = 4;
}
```

- 实验 proto **必须**有一个顶层字段，其类型与正式策略相同。
  - 该字段**必须**以正式资源类型命名。例如，如果实验针对 FirewallPolicy，则该字段**必须**命名为 `firewall_policy`。
  - 嵌入的 `policy` 消息中的名称**必须**是正式策略的名称。
- 用户准备提升实验时，**必须**将 `policy` 消息复制到正式策略中，然后删除实验。可以手动完成，也可以通过 `commit` 自定义方法完成。
- 产品**可以**支持针对单个正式策略同时预览多个实验。
  - 每个实验必须生成日志，并在每条日志前加上 `log_prefix`，以便用户将实验结果与正式策略行为比较。
  - 某个正式策略的实验配置数量**可以**设上限，且必须记录该上限。
- **必须**执行级联删除：如果正式策略被删除，所有实验**也必须**删除。
- `map<string,string>` [annotations][aip-128-annotations] **必须**允许客户端存储少量任意数据。

### 元数据

`preview_metadata` 记录预览实验的所有元数据。消息**必须**遵循 *RegularResourceType*`PreviewMetadata` 约定。这样，同一服务中每种资源类型都能为其实验唯一地定义 proto。

```proto
message PolicyPreviewMetadata {
  // 预览实验的状态可能值。
  enum State {
    // 默认值。此值未使用。
    STATE_UNDEFINED = 0;

    // 实验正在主动预览。
    ACTIVE = 1;

    // 实验预览已停止。
    SUSPENDED = 2;
  }

  // 实验预览的状态。
  State state = 1;

  // 预览实验时生成的所有日志共用的标识字符串。
  // 按此字符串搜索所有日志即可隔离实验结果。
  string log_prefix = 2;

  // 此实验最近一次开始预览的时间。
  google.protobuf.Timestamp start_time = 3;

  // 此实验最近一次停止预览的时间。
  google.protobuf.Timestamp stop_time = 4;
}
```

- `PolicyPreviewMetadata` **必须**包含上面 proto 中定义的字段。
  - 如果服务或资源需要，**可以**包含其他字段。
- 实验第一次被预览时，`preview_metadata` **必须**不存在。
  - 使用 `startPreview` 方法后，实验中才会出现该字段。
- 所有 `preview_metadata` 字段**必须**是仅输出字段。
- 开始或停止预览时，`state` 在 `ACTIVE` 和 `SUSPENDED` 之间变化，分别由 `startPreview` 或 `stopPreview` 自定义方法触发。
- 首次使用 `startPreview` 自定义方法时，系统**必须**创建 `preview_metadata` 并执行以下操作：
  - **必须**将 `state` 设置为 `ACTIVE`。
  - **必须**以当前时间填充 `start_time`。
    - 每次 `state` 变为 `ACTIVE` 时，**必须**更新 `start_time`。
  - **必须**设置系统生成的 `log_prefix` 字符串，该字符串是由系统开发者硬编码的预定义常量。
  - 给定资源类型的实验预览使用相同的值。例如，FirewallPolicy 使用 `FirewallPolicyPreviewLog`。
- 使用 `stopPreview` 自定义方法时，系统**必须**执行以下操作：
  - **必须**将 `state` 设置为 `SUSPENDED`。
  - **必须**以当前时间填充 `stop_time`。

### 方法

#### create

- 资源**必须**使用长时运行的 [Create][aip-133-long-running] 创建，且 `google.longrunning.operation_info.response_type` **必须**是 `PolicyExperiment`。
- 创建要预览的新实验**必须**支持以下使用场景：
  - 预览新策略。
  - 预览对已上线策略的更新。
  - 预览删除当前策略。
- 对更新和删除场景，实验中的 `policy` 字段**必须**包含正式策略的完整载荷，包括名称。
  - 用户**必须**将规则设置为要预览更新后的新状态。
  - 用户**必须**将规则设置为表示无操作，以预览删除。
- 预览新策略时，系统必须执行以下操作：
  - 如果系统不支持没有正式策略的嵌套集合，用户**必须**创建正式策略，并将规则设置为表示无操作。例如，无操作策略的规则**可以**为空。
    - 实验作为无操作策略的子资源创建。
- 如果系统支持针对正式策略预览多个实验，调用多次 `create` **必须**创建多个实验。

#### update

- 资源**必须**使用长时运行的 [Update][aip-134-long-running] 更新，且 `google.longrunning.operation_info.response_type` **必须**是 `PolicyExperiment`。
- `policy` 中的名称**不得**改变，但其他字段可以改变所预览的实验，因为该 `policy` 旨在替换正式策略，而正式策略的名称**不得**改变。
- 如果更新时 `state` 为 `ACTIVE`，系统**必须**将其设置为 `SUSPENDED`。
  - 这样用户可以轻松区分实验正在预览的不同版本。

#### get

- `PolicyExperiment` 资源类型**必须**包含标准 [Get][aip-131] 方法。

#### list

- `PolicyExperiment` 资源类型**必须**包含标准 [List][aip-132] 方法。
- 对 `PolicyPreviewMetadata` 进行过滤，可以判断哪些实验正在主动预览。
  - 例如，以下过滤字符串返回正在预览的实验：`preview_metadata.state = ACTIVE`。

#### delete

- 资源**必须**使用长时运行的 [Delete][aip-135-long-running] 删除，且 `google.longrunning.operation_info.response_type` **必须**是 `PolicyExperiment`。

#### startPreview

```proto
// 开始预览 PolicyExperiment。这会触发系统开始生成日志，
// 评估 PolicyExperiment。
rpc StartPreviewPolicyExperiment(StartPreviewPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:startPreview"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "PolicyExperiment"
    metadata_type: "StartPreviewPolicyExperimentMetadata"
  };
}

// startPreview 自定义方法的请求消息。
message StartPreviewPolicyExperimentRequest {
  // PolicyExperiment 的名称。
  string name = 1;
}
```

- 此自定义方法是必需的。
- `google.longrunning.Operation.metadata_type` **必须**遵循[长时运行操作][aip-151]的指导。
- 此方法**必须**触发系统开始生成日志来预览实验。
- 每当方法成功调用时，系统**必须**在 `PolicyPreviewMetadata` 中设置以下值：
  - `log_prefix` 为预定义常量。
  - `start_time` 为当前时间。
  - `state` 为 `ACTIVE`。
- 如果方法在规则表示无操作的实验上调用，系统**必须**预览正式策略的删除。

#### stopPreview

```proto
// 停止预览 PolicyExperiment。这会触发系统停止生成日志，
// 评估 PolicyExperiment。
rpc StopPreviewPolicyExperiment(StopPreviewPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:stopPreview"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "PolicyExperiment"
    metadata_type: "StopPreviewPolicyExperimentMetadata"
  };
}

// stopPreview 自定义方法的请求消息。
message StopPreviewPolicyExperimentRequest {
  // PolicyExperiment 的名称。
  string name = 1;
}
```

- 此自定义方法是必需的。
- `google.longrunning.Operation.metadata_type` **必须**遵循[长时运行操作][aip-151]的指导。
- 此方法**必须**触发系统停止生成日志来预览实验。
- 每当方法成功调用时，系统**必须**在 `PolicyPreviewMetadata` 中设置以下值：
  - `stop_time` 为当前时间。
  - `state` 为 `SUSPENDED`。

#### commit

资源**可以**暴露名为 `commit` 的新自定义方法来提升实验。系统将实验中的 `policy` 复制到正式策略，然后删除实验。

如果更合适，声明式客户端**可以**手动将实验中的字段复制到正式策略，再删除实验，而不是调用 `commit`。

```proto
// 提交 PolicyExperiment。将 PolicyExperiment 的 policy 消息
// 复制到正式策略，然后删除 PolicyExperiment。
rpc CommitPolicyExperiment(CommitPolicyExperimentRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=policies/*/experiments/*}:commit"
    body: "*"
  };
  option (google.longrunning.operation_info) = {
    response_type: "google.protobuf.Empty"
    metadata_type: "CommitPolicyExperimentMetadata"
  };
}

// commit 自定义方法的请求消息。
message CommitPolicyExperimentRequest {
  string name = 1;
  string etag = 2;
  string parent_etag = 3;
}
```

- `google.longrunning.Operation.metadata_type` **必须**遵循[长时运行操作][aip-151]的指导。
- 方法**必须**以原子方式将实验中的 `policy` 复制到正式策略，然后删除实验。
- 如果任何实验无法 `commit`，其预览**不得**停止，正式策略**不得**更新。
- 无论实验处于何种状态，都可以调用此方法。
- `etag` **必须**与实验的 etag 匹配，commit 才能成功。这是为了避免用户提交非预期版本的实验。
  - 如果未提供 `etag`，API **不得**成功，以防用户无意中提交与预期不同的实验版本。
  - **可以**提供 `parent_etag`，以保证实验覆盖正式策略的特定版本。
- 此方法不是幂等的；同一实验调用两次时，第二次**必须**返回 404 NOT_FOUND，因为实验已在第一次调用中删除。

### 正式策略 API 方法的变更

#### delete

- 删除正式策略**必须**删除所有实验。
- 如果要保留实验、同时抵消正式策略的效果，则**必须**将正式策略改为无操作策略，而不是使用此方法。

### 日志

日志对于用户判断是否应将实验提升为正式配置至关重要。

日志**必须**包含实验评估结果、与正式策略 etag 同时记录的实验 etag，并以 `log_prefix` 的值开头。
  - etag 字段帮助用户识别日志中评估的是哪一版正式策略和实验配置。
  - `log_prefix` 帮助用户将专门为实验预览生成的日志与其他场景生成的日志区分开。

总体而言，这些日志帮助用户决定是否将实验提升为正式配置。
