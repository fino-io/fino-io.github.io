# 基于条件的删除

少数 API 需要按过滤条件一次删除大量资源，而不是要求调用方提供每个资源名称。这是少见场景，仅适用于一次删除数千个或更多资源，普通批量 Delete（AIP-235）难以使用时。

## 指导

**重要：** 大多数 API **应**只使用 Delete（AIP-135）或 Batch Delete（AIP-235），**不应**按条件删除，因为删除通常不可逆，而过滤条件很容易导致大量数据被意外清除。

如果确有需要，API **应**定义名为 `Purge` 或 `DeleteByFilter` 的长时运行自定义方法，必须接收明确的过滤器、预览/校验选项和显式确认标志。过滤器应遵循 AIP-160，并且服务应在执行前报告受影响数量。

### 请求消息

请求应包含 `parent`、`filter`、`validate_only` 和必要的 `force`/确认字段。过滤器为空或过于宽泛时必须拒绝；服务应要求调用方有权限访问并删除过滤结果中的所有资源。

### 响应消息

响应应通过 `google.longrunning.Operation` 表示进度，最终 metadata 至少包含扫描、匹配、删除、失败和跳过数量。部分失败必须逐项报告，服务应保证重试不会重复删除已清除资源。
