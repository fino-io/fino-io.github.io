# 资源关联

API 有时存在无法用通常的树结构清晰表达的资源层级。例如，一个资源可能与两种其他资源类型分别构成多对一关系，而不是只与一种资源类型构成关系；或者，一个资源可能与另一种资源类型构成多对多关系。

## 指导

一个资源**最多必须**有一个规范父资源，`List` 请求**不得**要求两个不同的“父资源”才能工作。

### 多个多对一关联

如果一个资源与多种资源类型构成多对一关系，它**最多必须**选择其中一种作为规范父资源。该资源**可以**通过资源上的其他字段与其他资源建立关联。

```proto
message Book {
  // Book 的资源名称模式表明 Publisher 是规范父资源。
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  // 图书的资源名称。
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // 图书作者的资源名称。
  string author = 2 [(google.api.resource_reference) = {
    type: "library.googleapis.com/Author"
  }];
}
```

以这种方式列出具有多个关联的资源时，RPC **必须**按照 [AIP-132][] 的讨论，将 `string parent` 字段视为必填，且**不得**增加其他必填参数。RPC **应**包含 `string filter` 字段，使用户能够按照 [AIP-160][] 的讨论对其他资源关联进行过滤。

**注意：** 资源引用字段**必须**接受与被引用资源 `name` 字段相同格式的资源名称。

### 多对多关联

API 中的多对多关联不如关系型数据库中常见，部分原因是它们更难通过网络接口建模和呈现。

API **可以**包含多对多关系，且**应**使用包含资源名称列表的重复字段，并遵循 [AIP-144][] 中针对重复字段描述的原则。

```proto
message Book {
  option (google.api.resource) = {
    type: "library.googleapis.com/Book"
    pattern: "publishers/{publisher}/books/{book}"
  };

  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // 图书作者的资源名称。
  repeated string authors = 2 [(google.api.resource_reference) = {
    type: "library.googleapis.com/Author"
  }];
}
```

**注意：** 关于重复字段的更多信息（包括如何处理原子变更等常见问题），请参阅 [AIP-144][]。

如果使用重复字段限制过多，或者关联需要携带更多元数据，API **可以**使用一个子资源建模多对多关系，将其表示为两个一对多关联。

```proto
message BookAuthor {
  // BookAuthor 的资源模式表明 Book 是规范父资源。
  option (google.api.resource) = {
    type: "library.googleapis.com/BookAuthor"
    pattern: "publishers/{publisher}/books/{book}/authors/{book_author}"
  };

  // 图书与作者关联的资源名称。
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];

  // 作者的资源名称。
  string author = 2 [(google.api.resource_reference) = {
    type: "library.googleapis.com/Author"
  }];

  // 其他字段……
}
```

**注意：** 只有在关联关系需要额外元数据，或者使用重复字段的限制使该方式无法采用时，才建议使用子资源建模资源之间的关联。
