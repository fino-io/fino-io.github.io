# 平面

API 中的资源和方法可以按其所在或执行操作的*平面*进行划分。在 API
语境下，定义以下平面：

- 管理平面：统一的、面向资源的 API，主要用于配置和检索资源。
- 数据平面：读取和写入用户数据的异构 API（理想情况下也是面向资源的）。它通常连接到由管理平面配置的实体，例如虚拟机。

“平面”一词最初用于网络架构。尽管系统和网络架构通常还会定义其他平面（例如控制平面或电源平面），但 AIP 关注接口，因此本 AIP 不定义这些平面。

## 指导

### 管理平面

管理资源和方法主要用于配置、设置和审计数据平面所操作的资源。

例如，以下资源可以视为云服务商的管理资源：

- 虚拟机
- 虚拟私有网络
- 虚拟磁盘
- Blob 存储实例
- 项目或账号

### 数据平面

数据平面上的方法以各种数据格式操作用户数据，通常与通过管理平面 API 配置的资源交互。数据平面方法的示例包括：

- 在表中写入和读取行
- 向消息队列推送消息或从中拉取消息
- 将 Blob 上传到 Blob 存储实例或从中下载 Blob

由于高吞吐量、低延迟或遵循现有接口规范（例如 ANSI SQL）等要求，数据平面 API 在较大的 API 表面中可能是异构的。

- 为了便于使用，操作数据平面的资源和方法**可以**通过面向资源的管理 API 暴露。如果这样做，这些资源和方法**必须**遵守其他 AIP 中规定的管理平面要求（[AIP-131][] 至 [AIP-135][]）。

### 管理平面与数据平面的主要区别

- [声明式客户端][] 只操作管理平面。
- 数据平面通常处于面向用户功能的关键路径上，因此：
  - 可用性要求高于管理平面。
  - 对性能更敏感。
  - 需要更高的吞吐量。
