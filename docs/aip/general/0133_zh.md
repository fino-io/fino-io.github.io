# 标准方法：Create

在 REST API 中，通常向集合 URI（例如 `/v1/publishers/{publisher}/books`）发送 `POST` 请求，在集合中创建新资源。

面向资源的设计（[AIP-121][]）通过 `Create` 方法遵循这一模式：RPC 接收父集合和待创建资源，并返回创建后的资源。

## 指导

除非用户使用该能力没有价值，API **通常应**为资源提供 Create 方法。Create 方法用于在已有集合中创建新资源。

```proto
rpc CreateBook(CreateBookRequest) returns (Book) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
  };
  option (google.api.method_signature) = "parent,book";
}
```

- RPC 名称**必须**以 `Create` 开头，其余部分**应**使用资源消息名称的单数形式。
- 请求消息**必须**以 RPC 名称加 `Request` 命名；响应消息**必须**就是资源本身。
- 响应**应**包含完整资源，并**必须**包含调用方提供的字段（仅输入字段除外，或因 [AIP-157][] 而返回部分响应）。长时运行时，响应必须是解析为资源本身的 `google.longrunning.Operation`。
- HTTP 动词**必须**为 `POST`；目标集合**应**映射到 URI 路径，父资源**应**命名为 `parent`，集合标识符必须是字面量。
- `google.api.http` 注解**必须**包含 `body`，且必须映射到请求中的资源字段；其余字段**应**映射为查询参数。
- **应**恰好有一个方法签名，值为 `"parent,{resource},{resource}_id"`；不要求资源 ID 时可省略最后一项。
- 管理平面上的操作应具备[强一致性][strong consistency]：Create 完成意味着资源存在且用户可设置的值已达到稳定状态。

### 请求消息

```proto
message CreateBookRequest {
  string parent = 1 [(google.api.field_behavior) = REQUIRED];
  string book_id = 2 [(google.api.field_behavior) = REQUIRED];
  Book book = 3 [(google.api.field_behavior) = REQUIRED];
}
```

- 除非资源是顶层资源，否则**必须**包含 `parent` 字段；它**应**标注为必填，并**必须**标识所创建资源的类型。
- 管理平面资源**必须**包含 `{resource}_id`；数据平面资源**应**包含该字段。
- 资源字段**必须**存在，并映射到 POST 请求体。请求消息不得包含其他必填字段，也不应包含未由本 AIP 或其他 AIP 说明的可选字段。

### 长时运行的创建

创建耗时较长时，API **应**使用长时运行操作（AIP-151）：

```proto
rpc CreateBook(CreateBookRequest) returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{parent=publishers/*}/books"
    body: "book"
  };
  option (google.longrunning.operation_info) = {
    response_type: "Book"
    metadata_type: "OperationMetadata"
  };
}
```

`response_type` 和 `metadata_type` **都必须**指定；声明式友好的资源（AIP-128）**应**使用长时运行操作，即使请求立即完成，也可以返回已完成的 LRO。

### 用户指定的 ID

管理平面 API **必须**允许用户在创建时指定资源名称最后一段的 ID；数据平面 API **应**允许这样做。只有当资源允许完全相同的记录且不需要区分，或资源不会暴露给[声明式客户端][Declarative clients]时，才可例外。`{resource}_id` 必须位于请求消息而非资源中；可以是必填或可选字段，未提供时服务可以生成 ID。

```text
publishers/lacroix/books/les-miserables
publishers/012345678-abcd-cdef/books/12341234-5678-abcd
```

资源的 `name` 字段**必须**被忽略；方法签名应包含资源 ID；文档应说明 ID 的格式，并遵循 [AIP-122][]。若 ID 会造成资源名称重复，服务**必须**返回 `ALREADY_EXISTS`；若调用方无权看到冲突资源，则**必须**返回 `PERMISSION_DENIED`。REST API 中 `{resource}_id` 作为查询参数提供。

### 错误

请参阅[错误][errors]，尤其是[权限错误与资源不存在错误][permission-denied]。

## 设计缘由

[声明式客户端][Declarative clients]使用资源 ID 来识别资源、应用更新和解决冲突。若 ID 由系统生成，客户端无法在未本地保存 ID 的情况下重新找到资源，可能重复创建资源，并迫使所有引用它的资源更新为新 ID。用户指定 ID 还可以让客户端预先计算资源名称，并在其他资源中建立引用。
