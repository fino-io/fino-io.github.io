# 未设置的字段值

许多消息字段是可选的：用户可以不提供，或服务可以不填充输出字段。多数情况下，设置为默认值（如 `0`）与完全不设置没有实际区别，但有时二者语义不同。

## 指导

Protocol Buffers 服务**仅应**在需要区分默认值（`0`、`false` 或空字符串）与未设置时，才对基本类型使用 `optional`：

```proto
message Book {
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  // 0 与没有评分不同。
  optional int32 rating = 2;
}
```

大多数场景不应需要这种区分；如果替代设计无需区分，通常应优先采用替代设计，实践中 `optional` 通常只用于整数和浮点数。

**重要：** 跟踪字段是否出现，不等于记录 API 字段行为（AIP-203）。`optional` 字段仍可标注 `google.api.field_behavior = REQUIRED`；前者是 wire 格式和代码生成的 presence 选项，后者表达服务对字段的语义要求，二者可以同时使用。

### 向后兼容

给已有字段增加或删除 `optional` 是向后不兼容的变更，因为会改变编译后的 API。例如在 Go 中，基本类型字段可能从 `string` 变成 `*string`。因此客户端和服务端必须同步升级，风险较高。

## 设计缘由

字段行为注解和 `optional` 解决不同问题：`google.api.field_behavior` 说明字段是否必填、不可变等服务语义；proto3 `optional` 只控制字段 presence 的跟踪。它们并不互斥。
