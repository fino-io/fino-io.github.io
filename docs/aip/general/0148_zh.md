# 标准字段

跨 API 反复出现的概念应使用统一的字段名和行为；标准字段**应**只用于其对应概念。

## 指导

### 资源名称和 ID

每个资源**必须**有 `string name` 字段，用于资源名称（AIP-122），并且**应**作为资源的第一个字段。集合的父资源名称**应**使用 `string parent`，该字段通常出现在 List（AIP-132）和 Create（AIP-133）请求中。

### 其他名称

- `display_name`：可变、用户可设置的人类可读名称；不应要求唯一，长度**应**不超过 63 个字符，声明式友好资源**应**包含它。
- `title`：实体的正式名称，是 `display_name` 的更正式变体，不应要求唯一。
- `given_name`：人或动物的名；不得用 `first_name`，因为很多文化并不把名放在第一位。
- `family_name`：人或动物的姓；不得用 `last_name`，因为很多文化并不把姓放在最后。

### 时间戳

- `create_time`：仅输出的 `google.protobuf.Timestamp`，表示资源创建时间，可以是创建开始或完成时间。
- `update_time`：仅输出时间戳，表示最近更新；用户造成的任何变化**必须**刷新它，服务内部变化可以刷新。
- `delete_time`：仅输出时间戳，表示资源软删除时间；未软删除时必须为空。支持软删除的资源**应**提供它。
- `expire_time`：表示资源或属性不再有效的时间；服务可以提供不精确值，但资源不得早于该时间过期。
- `purge_time`：表示软删除资源将从系统清除的时间；资源不得早于该时间被清除，支持软删除的资源**应**包含它。

声明式友好资源**应**包含适用的 `create_time`、`update_time` 和 `uid`。

### 注解

可以增加 `map<string, string> annotations` 存储少量任意数据。该字段**必须**遵循 [Kubernetes 的注解限制][kubernetes annotations]以保持线兼容性，键**应**使用点分隔的命名空间。注解用于保存客户端工具自己的状态，不同于可用于 IAM 条件等服务端策略的标签。

### 众所周知的字符串字段

- IP 地址必须是 `string`，字段名为 `ip_address` 或以 `_ip_address` 结尾，并使用 `IPV4`、`IPV6` 或 `IPV4_OR_IPV6` 格式标注。
- `uid` 是仅输出的系统分配唯一标识符，必须是 [UUID4][uuid4]，并用 `UUID4` 格式扩展标注；声明式友好资源**应**包含它。

## 延伸阅读

标准化代码见 AIP-143；`etag`、`request_id`、`filter`、资源修订版本、`validate_only`、软删除分别见 AIP-154 至 AIP-164 的对应文档。

## 设计缘由

这些字段代表语义定义明确且通常有严格治理的概念。统一的 API 表面能够改善消费者工具、文档和平台整体体验。

## 历史

2023 年 7 月前，软删除资源的 `purge_time` 也曾称为 `expire_time`；引入 `purge_time` 是为了减少用户混淆。
