# 通用字段

大多数字段有确定类型或模式，这是开发者编写代码时依赖的契约。但在少数场景中，字段需要兼容多种模式，甚至完全自由格式。通用字段总体上应尽量少用，并选择能够满足用例的“最不通用”方案。

## 指导

### Oneof

`oneof` 可以表示类型联合，让用户或服务在其中选择一个字段；也可以用相同类型（通常是字符串）的多个字段表达语义差异。字段键不同，开发者可以判断哪个字段被填充。`oneof` 保留了最强的类型安全和语义，通常应优先使用；但不适合选项数量很大或需要级联大量 `oneof` 的结构。向已有 `oneof` 增加字段是非破坏性变更，但把字段移入或移出 `oneof` 会破坏 Go 等语言的 protobuf 存根兼容性。

### Map

键未知或由用户决定、但值类型相同且数量很多时，可以使用 map。Map 通常不适合作为通用字段，但当键名代表不同环境等行为时可能适用。

### Struct

`google.protobuf.Struct` 可以表示任意嵌套 JSON，适合服务预先不知道模式，或需要存取任意但结构化的用户数据的场景。若服务需要理解 Struct 的模式，应使用 [JSON Schema][JSONSchema] 描述。

### Any

`google.protobuf.Any` 可以传输任意序列化的 protobuf 及类型定义，但如果消费者没有对应 proto，它只能盲目转发；即使有 proto，也必须注册并手工反序列化。因此除非其他方案不可行，**不应**使用 `Any`。

[JSONSchema]: https://json-schema.org/
