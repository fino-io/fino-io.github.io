# 术语表

为了保持简洁，本文集中定义一些常用术语，而不是在每份 AIP 中分别定义。

## 指导原则

以下术语**应**在 AIP 中保持一致使用。

### API

应用程序编程接口（Application Programming Interface）。它可以是本地接口（例如客户端库），也可以是网络 API（见下文定义）。

### API 后端

实现 API 服务业务逻辑的一组服务器及相关基础设施。单个 API 后端服务器通常称为 API 服务器。

### API 消费者

使用 API 服务的实体。对于 Google API，通常是拥有客户端应用或服务器资源的 Google 项目。

### API 定义

API 的定义，通常通过 Protocol Buffers service 定义。任何数量的 API 服务都可以实现同一个 API 定义。

### API 前端

为 API 服务提供负载均衡、身份认证等通用功能的一组服务器及相关基础设施。单个 API 前端服务器通常称为 API 代理。

> **注意：** API 前端与 API 后端可以相邻运行，也可以相距很远。在某些情况下，它们可以被编译为一个应用程序二进制文件，并运行在同一个进程中。

### API 接口

API 规范 IDL 中用于归组 API 方法的元素，例如 Protocol Buffers 的 `service` 定义。它通常会映射到大多数编程语言中类似的高层归组机制，例如 `class` 或 `interface`。

### API 方法

API 中的单个操作。它通常在 Protocol Buffers 中表示为 `rpc` 定义，并映射为大多数编程语言中的 API 函数。

### API 生产者

生产 API 服务的实体。对于 Google API，通常是负责该 API 服务的 Google 团队。

### API 产品

API 服务及其相关组成部分（例如服务条款、文档、客户端库和服务支持）会作为一个 API 产品整体呈现给客户。例如 Google Calendar API。

> **注意：** 人们有时会直接把 API 产品称为 API。

### API 服务

一个或多个 API 的已部署实现，通过一个或多个网络地址对外提供服务，例如 Cloud Pub/Sub API。

### API 服务定义

用于定义 API 服务的 API 定义（`.proto` 文件）与 API 服务配置（`.yaml` 文件）的组合。Google API 服务定义的 Schema 是 `google.api.Service`。

### API 服务端点

API 服务用于处理 API 请求的网络地址。一个 API 服务可以有多个 API 服务端点，例如 `https://pubsub.googleapis.com` 和 `https://content-pubsub.googleapis.com`。

### API 服务名称

API 服务的逻辑标识符。Google API 使用符合 RFC 1035 DNS 规则的服务名称，例如 `pubsub.googleapis.com`。

### API 标题

API 服务面向用户的产品标题，例如 “Cloud Pub/Sub API”。

### API 请求

对 API 方法的一次调用。它通常作为计费、日志记录、监控和速率限制的单位。

### API 版本

API 或一组共同定义的 API 的版本。API 版本通常由类似 `v1` 的字符串表示，并出现在 API 请求和 Protocol Buffers 包名中。

### 客户端

通过调用 API 执行特定任务的程序，或以用户可访问的方式暴露 API、处理静态资源数据的通用工具，例如 CLI。

客户端包括：

- 命令行界面；
- 库，例如某种编程语言的 SDK；
- 从 API 读取资源后，对其 JSON 表示执行操作的脚本；
- 工具，例如[声明式客户端](#声明式客户端)；
- 可视化界面，例如 Web 应用。

### Google API

由 Google 服务公开的网络 API。大多数 Google API 托管在 `googleapis.com` 域名下。不包括客户端库、SDK 等其他类型的 API。

### 声明式客户端

声明式客户端也称基础设施即代码（Infrastructure as Code，IaC）客户端。它消费一种标记语言或代码，其中表示了 API 暴露的资源，然后执行适当的命令式操作，使资源达到期望状态。声明式客户端会比较服务器端资源属性与客户端定义的值，以确定需要执行哪些变更以及更新是否成功。这个比较过程要求服务将客户端设置的字段视为只读，并认真保留这些值。

声明式客户端抽象的复杂性包括：

- 确定达到期望状态所需的命令式操作（创建、更新、删除）；
- 确定这些命令式操作的执行顺序。

[Terraform](https://www.terraform.io/) 是这类客户端的一个例子。

### 用户

直接使用 API 的人，例如使用 cURL 的人。这个术语用于区分 AIP 中的人类用户与程序化客户端。

### 网络 API

跨计算机网络运行的 API。网络 API 使用 HTTP 等网络协议通信，通常由与 API 消费者不同的组织生产。
