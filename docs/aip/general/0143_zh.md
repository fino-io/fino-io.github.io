# 标准化代码

语言、国家、货币等常见概念通常已有用于数据通信和处理的标准代码（通常由[国际标准化组织][iso]制定）。使用代码可以避免同一概念有多种文字表达，例如 “United States” 与 “USA”。

## 指导

存在广泛使用的标准代码时，表示该概念的字段**应**在输入和输出中使用标准代码。

```proto
message Book {
  // 表示图书原始语言的 IETF BCP-47 语言代码。
  string language_code = 99;
}
```

- 字段**必须**使用标准要求的数据类型（通常是 `string`）。即使允许值很少，也**不应**使用 enum，因为跨多个 API 使用时会产生令人困惑的查找表。
- 字段**必须**说明所遵循的标准，最好提供标准本身或权威说明的链接。

### 内容类型

表示媒体类型时，**应**使用 IANA 的媒体类型（MIME 类型），字段名**应**为 `content_type`。

### 国家和地区

国家或地区字段**应**使用 ISO 3166-1 alpha-2 代码，字段名**应**为 `country_code` 或 `region_code`，而不是 `country` 或 `region`。

### 货币

货币字段**应**使用 ISO 4217 三字母代码，字段名**应**为 `currency_code`。金额应结合 `google.type.Money` 使用。

### 语言

语言字段**应**使用 IETF BCP-47 语言标签，字段名**应**为 `language_code`。

### 时区

时区字段**应**使用 IANA 时区数据库名称，如 `America/Los_Angeles`，字段名**应**为 `time_zone`。

## 设计缘由

代码使 API 可以跨语言、跨产品一致地表示概念，并避免为同一概念维护多个本地化字符串。字段名应描述代码代表的概念，而不是把代码格式误当成概念本身。

[iso]: https://www.iso.org/
