# 稳定性级别

AIP 使用以下术语描述 API 组件的稳定性。它们大致对应 Google Cloud 的 Alpha、Beta、GA，但并不完全相同；GCP 还会施加额外承诺。

## Alpha

Alpha 组件快速迭代，用户范围应经过控制且可管理，所有用户**必须**能够接受变化。Alpha **必须**允许并预期破坏性变更，服务应尽量直接沟通变化。

## Beta

Beta 组件已有更广泛用户，核心设计通常稳定，但仍可能发生破坏性变更。破坏性变更应提前通知，并提供迁移路径；除非明确说明，Beta 不应被视为永久契约。

## Stable

Stable 组件代表长期支持的契约。服务**必须**遵守 [AIP-180](./0180.md)，不能在同一 major 版本中破坏旧客户端。

### Major 版本

需要破坏性变更时应发布新的 major 版本，并保持旧版本一段明确的弃用期。不同 major 版本可以并存，但应避免让用户长期维护多个版本。

### 孤立变更

即使组件整体稳定，也可能新增独立的实验性方法、字段或资源；这些组件应单独标注稳定性，不应因所在服务稳定就被误认为稳定。

### 紧急变更

安全、合规或严重可靠性问题可能需要紧急破坏性修复。服务应记录原因、影响范围、通知和回滚方案，并尽快恢复稳定契约。
