# 作业

有些任务耗时很长，且不适合使用短暂的[长时运行操作][aip-151]：任务可能需要重复运行，或配置任务与执行任务需要不同权限。此时 API **可以**定义 `Job` 资源，表示具有独立设置、配置和执行过程的任务。

## 指导

```proto
message WriteBookJob {
  option (google.api.resource) = {
    type: "library.googleapis.com/WriteBookJob"
    pattern: "publishers/{publisher}/writeBookJobs/{write_book_job}"
  };
  string name = 1 [(google.api.field_behavior) = IDENTIFIER];
  string display_name = 2;
}
```

Job 是持久资源，应使用标准 Get、List、Create、Update、Delete 方法。执行作业应使用名为 `Run` 的自定义方法，该方法通常返回 `google.longrunning.Operation`，Operation 完成后返回执行结果或执行资源。

### Run 方法

Run 方法应作用于 Job 资源，并使用类似以下 URI：

```proto
rpc RunWriteBookJob(RunWriteBookJobRequest)
    returns (google.longrunning.Operation) {
  option (google.api.http) = {
    post: "/v1/{name=publishers/*/writeBookJobs/*}:run"
    body: "*"
  };
}
```

运行参数应放在请求消息中，而不是修改 Job 的配置。调用方应能通过 Operation 查询单次执行的状态和结果；多次运行同一 Job 必须产生可区分的执行记录。

### Run 请求消息

请求应包含 `name`，标注为必填并引用 Job 资源类型；不得把每次执行的临时参数写回 Job。执行有独立资源时，应在 Job 下建立 executions 子集合。

### 执行与结果

执行记录应包含开始时间、结束时间、状态、错误和输出引用。服务可以保留历史执行，也可以按文档规定的策略清理；清理执行记录不得删除 Job 本身。需要重试时，应创建新的执行并保留与原执行的关系。
