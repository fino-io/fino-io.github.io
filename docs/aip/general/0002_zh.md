# AIP 编号

AIP 系统用于为 API Improvement Proposal 建立索引、维护单一事实来源，并以协作、透明的方式持续迭代。

本文说明 AIP 的编号体系。

## 分配 AIP 编号

AIP 编辑负责在一份 AIP 作为草案进入评审时为其分配编号。重要的是：所有 AIP 都有编号，不仅是已批准的 AIP。[AIP 索引](https://google.aip.dev/general) 会清晰区分已批准且具有约束力的 AIP 与仍在讨论中的 AIP。

编辑可以为一组具有共同特征的 AIP 预留一个编号区间，例如仅适用于某一部分 API 的 AIP。

除此之外，AIP 编号按任意方式分配。通常，编辑会从编号池中取出下一个编号分配给草案；但在有助于记忆或表达的情况下，也可能使用特殊编号或玩笑编号。

## AIP 编号区间

当前认可的 AIP 编号区间如下：

### 通用范围

- **1–99：** 预留给元规范 AIP（通常与流程相关）。
- **100–999：** 通用 API 设计指导。

### Google 产品领域

- **2700–2799：** Apps（Google Workspace）
- **2500–2599：** Cloud
- **3000–3099：** Actions on Google
- **3200–3299：** Firebase
- **4100–4199：** Auth libraries
- **4200–4299：** Client libraries
- **4600–4699：** Geo

如果团队希望申请一个专用于自身 API 指导或文档的编号区间，请联系 `api-editors@`。

## 变更记录

- **2019-10-03：** 将 3000–3099 区间分配给 Actions on Google。
- **2019-01-26：** 将通用 API 设计指导区间扩展至 100–199。
- **2018-10-24：** 将 4600–4699 区间分配给 Google Geo。
- **2018-10-02：** 将 2500–2599 区间分配给 Google Cloud Platform。
- **2018-10-02：** 将 2700–2799 区间分配给 Google Workspace。
