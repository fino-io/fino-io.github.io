# 20 · 资料、方向与常见问题

本章目标：保留一条清晰的学习主线，遇到具体问题时知道去哪里查、怎样验证。以下方向安排是结合本指南项目提出的学习建议，掌握程度以独立完成与解释程序为准。资料核对日期：2026-10-08。

官方教程假定读者已了解基本编程概念，完全初学者可先完成本指南 01–05 或 CS50P 的入门主题。CS50P 以 Python 为主，若还需要算法、数据结构与计算机基础，应另行安排对应学习。不要把收藏了多少资料当作学习进度。

选择资料时确认适用的 Python 与库版本、示例是否能运行、是否解释失败情况。中文资料用于建立理解，遇到术语和版本差异时核对项目官方文档。旧教程中的 Python 2 写法、安装方式和已弃用 API 不直接照搬。

## Web 与 API 开发方向

建议顺序：HTTP 与 JSON → SQL 和事务 → 一个 Web 框架 → 接口测试 → 鉴权与资源权限 → 部署、日志和数据库迁移。

API 为主的项目可从 [FastAPI 官方教程](https://fastapi.tiangolo.com/tutorial/) 出发，需要后台管理、用户系统和完整站点时可读 [Django 入门](https://docs.djangoproject.com/en/stable/intro/)。先选一个完成作品，再比较不同框架。补充 SQLAlchemy、Alembic 等工具时围绕实际存储和迁移需求学习。

阶段作品：扩展 [任务管理 API](./project-api)，实现用户隔离与按状态查询。验收不只检查“能登录”，还应验证一个用户不能读取或修改另一个用户的任务，并演练重启、数据库迁移和备份恢复。

## 数据分析方向

建议顺序：CSV 和数据契约 → pandas → SQL → 统计基础 → 可视化 → 报告自动生成。数组运算和广播可从 [NumPy 官方学习资源](https://numpy.org/learn/) 入手，表格操作查阅 [pandas 入门教程](https://pandas.pydata.org/docs/getting_started/intro_tutorials/index.html)。

阶段作品：扩展 [月度消费分析](./project-data)，增加分类占比和质量报告。明确缺失值、重复记录、币种、时区和统计范围；图表标注单位与样本数，金额总和能够回到原始记录核对。Notebook 用于探索，最终交付的规则放入能从头执行的脚本。

## 自动化与工具开发方向

建议顺序：Path 和文件 → argparse → 日志与配置 → HTTP → 调度与幂等 → 打包与分发。需要更复杂的 CLI 时再选 Click 或 Typer；网页交互需要真实浏览器时复用 Playwright，避免自写浏览器控制框架。

阶段作品：实现批量文件整理工具。先输出预览清单，再执行移动；记录每个操作的结果，避免覆盖同名文件。重复执行时结果应可预期，任务失败后能定位到具体文件。定时运行还要处理超时和重复启动。

## 机器学习方向

先掌握 NumPy、pandas、概率统计和线性代数，再学习 [scikit-learn 入门](https://scikit-learn.org/stable/getting_started.html)。理解训练与评估数据的分离、基线模型、指标、交叉验证和数据泄漏后，再按需求进入深度学习框架。

阶段作品：对公开的合成或教学数据建立一个分类基线。记录数据划分、特征处理与评估结果，预处理规则只从训练数据学习；与简单基线比较，并解释错误案例。只得到一个较高分数还不足以证明模型能用于真实场景。

## 环境与依赖的常见问题

### 安装过包，为什么还是无法导入？

先确认解释器：`python -c "import sys; print(sys.executable)"`，再运行 `python -m pip show 包名`。编辑器、终端和 Notebook 可能使用三个不同环境。检查文件名是否遮蔽标准库，例如 `json.py` 或 `typing.py`。导入名也未必与包安装名一致，应以库文档为准。

### pip、venv、uv 和 conda 应该选哪个？

先理解 venv 负责环境隔离、pip 负责安装包。普通应用可继续用这套组合，或用 uv 统一管理项目与锁文件；需要不同系统库和科学计算环境时可按团队要求使用 conda。为一个项目选一套明确流程，避免用多个工具交替修改同一环境。详见 [环境与工具链](./toolchain) 和 [项目结构](./modules)。

### Python 版本升级后项目为什么失败？

检查项目的 `requires-python`、依赖支持范围与锁文件，不要直接复用旧 `.venv`。重新创建环境，先安装并运行测试，再处理弃用提示。应用升级与库发布不同：应用关注可复现环境，库还需验证声明支持的版本范围。

## 语言与运行行为的常见问题

### 为什么修改一个列表会影响另一个变量？

赋值让两个名字引用同一个对象，浅复制也只复制外层。先画出引用关系，再决定需要新容器、深复制还是原地修改。函数默认参数也可能共享可变对象，使用 `None` 在调用时创建。详见 [集合](./collections) 和 [函数](./functions)。

### 已经写了类型标注，为什么错误数据仍能传进来？

注解通常不自动校验运行时值。静态检查发现代码层面的类型问题，外部 JSON、配置和文件仍需解析与验证；`TypedDict` 也不会把普通 dict 变成校验模型。业务边界复用 Pydantic 或明确的解析函数。详见 [类型标注与边界校验](./typing)。

### async 为什么没有变快，甚至卡住？

async 主要让等待 I/O 的任务交错执行，不会自动加速 CPU 运算。同步请求、`time.sleep` 或重计算会阻塞事件循环。先测量瓶颈，再选择同步、线程、进程或异步，并限制并发数量与总等待时间。详见 [并发](./concurrency)。

### 代码在 Notebook 能运行，换成脚本却失败？

检查隐藏的执行顺序、工作目录、环境和未保存的变量。重启内核并从第一格执行；再将稳定规则提取为函数。相对文件路径基于工作目录，不一定是脚本所在位置，输入路径应明确提供。

## 学习与求助的常见问题

### 什么时候需要学装饰器、元类和性能优化？

装饰器与生成器有常见用途，可按第 08 章学习。元类、描述符和 C 扩展等专题，等读库源码或解决真实需求时再深入。性能优化从测量、算法和 I/O 次数开始，不提前用多进程替代清晰的数据处理。

### 怎么判断自己已经掌握？

能够不照抄完成一个变化需求，解释输入和输出，处理至少一个失败场景，并给出可复现测试。还应能说明为什么选择这个库、哪些限制仍存在。具体交付标准见 [从练习到完整项目](./projects)。

### 如何提出容易被回答的问题？

提供目标、Python 与依赖版本、运行命令、最小可复现代码、完整 traceback，以及预期和实际结果。使用合成输入替换私人数据，删除凭据。先查异常名称和官方 API 文档，保留自己已尝试的方法，避免只贴“运行不成功”。
