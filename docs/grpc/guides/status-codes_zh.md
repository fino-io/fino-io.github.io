### 概述
所有 RPC 都会导致 `status` 返回给客户端。  `status` 对象由整数代码和字符串错误描述组成。服务端（或库级别错误的 gRPC 库）选择它为给定 RPC 返回的状态。应用程序应仅使用下面定义的值。

当发生错误情况时，gRPC 库可能会生成相应的 `status`。库可以在客户端或服务端执行此操作。 gRPC 库仅生成预定义状态码的子集。这允许应用程序确保它看到的任何其他代码实际上是由应用程序返回的（尽管服务端也可以返回 gRPC 库生成的代码之一）。

有关如何使用状态码，请参阅[错误处理](https://grpc.io/docs/guides/error)用户指南。

### 状态码的完整列表
gRPC 使用一组明确定义的状态码作为 RPC API 的一部分。

以下状态码永远不会由库生成，仅由用户代码生成：
- 无效参数
- 未找到
- 已经存在
- 失败的前提条件
- 中止
- 超出范围
- 数据丢失

#### 状态码的完整列表

|代码|ID| 描述 |
|--------------------|--------|------------------------------------------------------------------------------------|
|好的|0|不是错误；成功返回。|
|取消|1|操作通常被调用者取消。|
|未知|2|未知错误。例如，当从另一个地址空间接收到的 `Status` 值属于该地址空间中未知的错误空间时，可能会返回此错误。此外，由未返回足够错误信息的 API 引发的错误也可能会转换为此错误。|
|INVALID_ARGUMENT|3|客户端指定了无效参数。请注意，这与 `FAILED_PRECONDITION` 不同。 `INVALID_ARGUMENT` 表示无论系统状态如何都有问题的参数（例如，格式错误的文件名）。|
|DEADLINE_EXCEEDED|4|操作完成之前截止时间已过。对于更改系统状态的操作，即使操作已成功完成，也可能会返回此错误。例如，服务端的成功响应可能会延迟足够长的时间，以致截止时间到期。|
|未找到|5|未找到某些请求的实体（例如文件或目录）。服务端开发人员请注意：如果整个类别的用户的请求被拒绝，例如逐步推出功能或未记录的许可名单，则可以使用 `NOT_FOUND`。如果一类用户中的某些用户的请求被拒绝，例如基于用户的访问控制，则必须使用 `PERMISSION_DENIED`。|
|已经存在|6|客户端尝试创建的实体（例如文件或目录）已存在。|
|没有权限|7|调用者没有执行指定操作的权限。 `PERMISSION_DENIED` 不得用于因耗尽某些资源而导致的拒绝（对于这些错误，请使用 `RESOURCE_EXHAUSTED` 代替）。如果无法识别调用者，则不得使用 `PERMISSION_DENIED`（对于这些错误，请使用 `UNAUTHENTICATED` 代替）。此错误代码并不意味着请求有效或请求的实体存在或满足其他先决条件。|
|RESOURCE_EXHAUSTED|8|某些资源已耗尽，可能是每个用户的配额，或者可能是整个文件系统空间不足。|
|失败_前提条件|9|操作被拒绝，因为系统未处于操作执行所需的状态。例如，要删除的目录非空、rmdir 操作应用于非目录等。服务实现者可以使用以下准则来在 `FAILED_PRECONDITION`、`ABORTED` 和 `UNAVAILABLE` 之间做出决定： (a) 如果客户端可以仅重试失败的调用，则使用 `UNAVAILABLE`。 (b) 如果客户端应在更高级别重试（例如，当客户端指定的测试和设置失败时，指示客户端应重新启动读取-修改-写入序列），请使用 `ABORTED`。 (c) 如果客户端在系统状态明确修复之前不应重试，请使用 `FAILED_PRECONDITION`。例如，如果“rmdir”由于目录非空而失败，则应返回 `FAILED_PRECONDITION`，因为除非从目录中删除文件，否则客户端不应重试。|
|中止|10|操作被中止，通常是由于并发问题，例如定序器检查失败或事务中止。请参阅上面的指南以在 `FAILED_PRECONDITION`、`ABORTED` 和 `UNAVAILABLE` 之间做出选择。|
|超出范围|11|尝试的操作超出了有效范围。例如，查找或读取文件末尾之后的内容。与 `INVALID_ARGUMENT` 不同，此错误指示如果系统状态发生更改则可能会修复的问题。例如，如果要求读取不在 [0,2^32-1] 范围内的偏移量，32 位文件系统将生成 `INVALID_ARGUMENT`，但如果要求读取超过当前文件大小的偏移量，则会生成 `OUT_OF_RANGE`。 `FAILED_PRECONDITION` 和 `OUT_OF_RANGE` 之间有相当多的重叠。我们建议在应用时使用 `OUT_OF_RANGE` （更具体的错误），以便迭代空间的调用者可以轻松查找 `OUT_OF_RANGE` 错误以检测它们何时完成。|
|未实现|12|此服务未实现或不支持/启用该操作。|
|内部的|13|内部错误。这意味着底层系统所期望的一些不变量已经被打破。该错误代码是为严重错误保留的。|
|不可用|14|该服务目前不可用。这很可能是一种瞬态情况，可以通过后退重试来纠正。请注意，重试非幂等操作并不总是安全的。|
|数据丢失|15|不可恢复的数据丢失或损坏。|
|未经验证|16|该请求没有用于该操作的有效认证凭据。|
