# 10.5. 可执行文件、交叉编译与部署

先修建议：[包、模块、依赖与发布](./modules)、[HTTP 服务与 Web 框架](./web)、[静态分析、Linter 与漏洞检查](./quality)。

## 产物、配置与运行环境共同构成交付 {#concept-1}

构建出的可执行文件只是交付的一部分。目标系统和架构、证书、配置、数据路径、外部库与关闭预算，也决定程序能否正确运行。

```mermaid
flowchart LR
  C["源码、依赖、工具链、目标平台"] --> B["构建并记录版本"] --> P["可执行文件"]
  P --> R["目标环境启动"]
  E["配置、证书、数据与外部依赖"] --> R
  R --> V["检查关键行为、观测与关闭"]
```

纯 Go 交叉编译较直接，cgo 还涉及目标 C 工具链。服务关闭时先停止新工作，再等在途操作和后台任务，最后释放依赖；把数据库先关掉会让还在处理的请求访问已关闭资源。

## 配置先校验再启动 {#concept-2}

配置从环境变量、参数或配置文件读取，入口集中解析并转换成具名配置。端口、数据库连接、超时和队列长度在启动时校验；必须配置缺失时明确失败。区分合理默认值与隐藏错误，生产数据库地址不能默默回落到本地。

凭据由部署平台的 secret 机制传入，不写进源码、镜像层或启动日志。日志记录环境、服务版本与重要限额，屏蔽密钥。外部输入限制长度、数量和超时，TLS、认证和加密复用成熟实现。

## 构建与平台边界 {#concept-3}

```sh
go fmt ./...
go test ./...
go vet ./...
go build -trimpath -o bin/server ./cmd/server
```

对于没有 cgo 依赖的项目，可交叉编译：

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bin/server-linux ./cmd/server
```

架构要与部署节点对应。用了 cgo 的驱动或本地库时不能假设关闭 cgo 后仍可运行，应确认工具链与动态库需求。记录源代码版本、工具链、依赖和构建参数，部署前在目标环境做启动与接口检查。

容器需要非 root 用户、CA 证书、必要时区数据和可写目录规划；最小镜像不一定自带这些文件。端口监听、健康检查与关闭信号都要验证。无需依赖时直接部署可执行文件也很合适，不为小工具强行加入 Kubernetes。

## 安全与依赖检查 {#concept-4}

使用 [Go 官方安全工具](https://go.dev/doc/security/)中的 govulncheck，按 [govulncheck 使用说明](https://pkg.go.dev/golang.org/x/vuln/cmd/govulncheck)安装兼容工具版本并运行：

```sh
govulncheck ./...
```

安装最新版工具通常需要当前受支持工具链；团队将确定的工具版本写入 CI 或工具清单。检查发现的调用路径、修复版本和测试影响，不仅关注依赖是否“出现过漏洞”。静态扫描不能替代输入校验、授权、限流与 secret 管理。

## 健康、日志与关闭 {#concept-5}

| 能力 | 应表达什么 |
| --- | --- |
| 存活检查 | 进程能运行，避免依赖暂时故障触发无休止重启。 |
| 就绪检查 | 当前是否适合接收业务流量，可检查关键依赖。 |
| 日志 | 请求 ID、操作、持续时间、稳定错误字段，避免高敏内容。 |
| 指标 | 请求量、延迟、错误率、并发、连接池等待与队列长度。 |
| Trace | 跨服务关键调用链，统一采样与上下文传播。 |
| 优雅关闭 | 停止新流量、等待在途操作、取消后台任务、关闭依赖。 |

指标标签不能用无限增长的用户 ID、原始 URL 或任务 ID，否则会产生高基数。停止接收请求后再释放数据库，避免在途请求访问已经关闭的连接。Shutdown 的预算应小于平台允许的终止宽限时间。

## 发布与回滚的一次演练 {#concept-6}

打包可执行文件、配置示例和版本说明；测试环境启动并检查健康、关键接口、关闭行为；保留上一版本产物；回滚同时考虑数据库迁移兼容性。服务配置与数据不塞进二进制更新包，secret 从平台提供。

本文是交付学习流程，实际项目复用已有 CI/部署系统。先交付一台机器的可执行文件，再按需要加容器和多实例，不为了展示技术堆砌平台。

## 练习与验收 {#lab}

1. 错误端口、空数据库地址与无效超时均能在启动时失败。
2. 在目标平台构建并运行，验证证书和时区相关能力。
3. 对服务发送终止信号，确认请求与后台任务收拢。

验收：构建可复现、配置可检查、失败可定位，敏感信息不出现在产物和日志中。
